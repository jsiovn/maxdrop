# The oracle: what 3ds Max says about a scene

`tools/oracle/dump_scene.ms` asks 3ds Max itself about a scene and writes the answer as JSON. MaxDrop's reader
is checked against these files instead of against itself: transforms, hierarchy, bounding boxes, mesh counts,
instances, layers, flags, materials and units are what Max reports, not what the reader thinks the file says.

`tests/fixtures/<name>.oracle.json` is the oracle of `tests/fixtures/<name>.max`, generated by the script and
never edited by hand. `tests/test_oracle.py` checks that every fixture has one, that each is canonical and
consistent, and that none holds a user name, machine name or path.

## Running it

Needs 3ds Max (the committed files come from 3ds Max 2020). Run the lines in the MAXScript Listener, or send them
through any bridge to a running Max (this project uses the 3dsmax-mcp bridge). `dumpFile` and `dumpFolder` reset
the scene: run them in a session with nothing to keep.

```maxscript
fileIn @"<repo>\tools\oracle\dump_scene.ms"
MaxDropOracle.dumpScene @"<out>.json"                  -- the scene that is open
MaxDropOracle.dumpFile @"<scene>.max" @"<out>.json"    -- reset, load, dump, reset
MaxDropOracle.dumpFolder @"<repo>\tests\fixtures" @"<repo>\tests\fixtures"   -- every fixture
```

Each call returns one line: node count, dump time, load time (`dumpFolder` adds a last line with the number of
files and failures). `dumpFile` loads with `quiet:true` and `useFileUnits:true`, so every value is in the file's
own units, and afterwards puts back the session's unit setup (system unit and scale, display units), which
loading a file changes. A file that fails to load returns `MaxDrop oracle: failed: ...` and leaves no output file:
an older dump at that path is deleted first. Every node is evaluated at frame 0 (`time`), whatever frame the file
was saved at.

After a fixture changes (`tools/fixtures/<name>.ms`, then sanitize and check, see CONTRIBUTING.md), run
`dumpFolder` again and commit the `.max` and its `.oracle.json` together. The dump reads the committed, sanitized
file, not the original Max saved.

**Scenes that are not ours** (the corpus): write the dump outside the repository. Their JSON holds object,
material and layer names of commercial assets and is never committed or quoted.

## Determinism

The same file gives the same bytes: keys in sorted order at every level, floats printed with 6 significant digits
(`%.6g`, the precision of Max's single-precision floats; `-0` is written `0`, inf and nan `null`), every character
outside printable ASCII escaped as `\uXXXX`, two-space indent, LF line ends, a final newline. Node handles are the
same after a reset and reload: they are kept in the file, not numbered at load (a node deleted before saving
leaves a gap that is still there after loading). Only the base name of the file is written, never a path.

`.gitattributes` marks `*.oracle.json` as `-text`, so git never converts their line ends: the files stay LF on
every checkout, and `tests/test_oracle.py` compares their bytes.

## Fields

Top level:

| Key | Value |
|---|---|
| `file` | Base name of the scene file (`null` for an unsaved scene). |
| `file_version` | `getMaxFileVersionData`: `[format version, version of the Max that saved it]`, e.g. `[20000, 22000]` = saved by 3ds Max 2020 as a 2018 file (checked by saving with `saveAsVersion:2018`). |
| `layers` | Every layer in layer-manager order: `name`, `hidden`, `frozen`, `renderable` (`isHidden`, `isFrozen`, `renderable` of the layer; whether a hidden or frozen parent layer shows in its child's is not known: no fixture has one), `parent` (the name of its parent layer, `getParent()`; `null` at the top level). |
| `material_graph` | Every material and map reachable from a node's material, see [below](#the-material-graph). |
| `materials` | The materials assigned to nodes, in order of first use in the node walk: `index`, `name`, `class_id`, `class_name`, `sub_count` (sub-materials, e.g. of a Multi/Sub-Object). |
| `max_version` | The Max that made the dump: `[release, year]`, e.g. `[22000, 2020]`. |
| `node_count` | Number of entries in `nodes`. |
| `nodes` | Every node of the scene, see below. |
| `oracle_version` | Version of this layout (2: `material_graph` added; 3: the modifier context, switches and name of each modifier; 4: `shape`; 5: `eval_maps`; 6: `camera` and `render`; 7: a layer's `parent`, and a node's `hidden` and `frozen` its own flags; 8: a block's `controllers`; 9: `eval_mesh`). |
| `render` | The render settings: `width`, `height` (pixels), `pixel_aspect`, and `camera`: the handle of the camera of the view 3ds Max renders (the locked render view, `rendViewIndex`, else the active viewport; `viewport.getCamera`), `null` when that view looks through no camera. |
| `renderer` | The current renderer: `class_id`, `class_name`. |
| `time` | The frame every node was evaluated at: always 0. |
| `units` | `system_type` (e.g. `millimeters`), `system_scale`, `display_type` (`Generic`, `Metric`, `US`, `Custom`), `display_metric`, `display_us`. |

Each node (scene order = a pre-order walk from the root: a node, then its children in Max's child order, so a
parent always comes before its children):

| Key | Value |
|---|---|
| `index` | Position in `nodes`, from 0. |
| `name` | Node name. Names are not unique; `handle` is. |
| `handle` | Max's node handle (`node.handle`), unique in the scene. |
| `parent` | Handle of the parent, `null` at the top level. |
| `base_class_id` | Class id of the base object (the bottom of the modifier stack) as `["0x<classID[1]>", "0x<classID[2]>"]`, the `classA, classB` pair of the file's class directory. Dispatch on this, never on the name. |
| `base_class_name` | MAXScript class name of the base object, for people. |
| `base_superclass` | Super class id of the base object, decimal (16 = geometry, also camera and light targets; 32 = camera; 48 = light; 64 = shape; 80 = helper, also Particle Flow operators). |
| `base_verts`, `base_faces` | Counts of the base object: polygons for Editable Poly, triangles for Editable Mesh, `null` for every other class. |
| `eval_verts`, `eval_faces` | The evaluated world-state mesh (`snapshotAsMesh`, after every modifier) as triangles; `null` when the node is not geometry or yields no mesh (lights, helpers, targets, particle flow events). |
| `eval_maps` | `null` unless a modifier of the node is a UVW Map. Then, per map channel one of its UVW Maps writes (`mapChannel`, or 0 for the vertex color channel), ascending: `channel` and `corners`, one entry per corner of every triangle of that evaluated mesh in face order, `[x, y, z, nx, ny, nz, u, v, w]`: the world position (`getVert`), the face normal (`getFaceNormal`, world space) and the map vertex (`meshop.getMapVert` of `meshop.getMapFace`). |
| `eval_mesh` | `null` unless the node has a modifier and `eval_faces` is not `null` (a switched-off Extrude leaves a shape: `null`). Then what that evaluated mesh carries per face: `material_ids`, per material ID (`getFaceMatID`, 1-based as 3ds Max shows it; an ID no face has is left out), ascending, `[id, up, down, side]`: its triangles by the way they face in **object space**: the three vertices of `snapshotAsMesh` taken back by the inverse object transform, the z of their winding normal, normalized, above 1e-4 `up`, below -1e-4 `down`, else (a degenerate face too) `side`. The counts add up to `eval_faces`. On extrude.max the world normals give the same counts (its mirrored node's transform is a point reflection, which keeps a winding normal), so the fixture does not choose the space; object space is the one the Extrude rule (cap facing +Z ID 1, -Z ID 2, sides 3) and the reader's mesh are in. `map_channel_1`: `null` without channel 1 support (an Extrude without mapping coordinates), else `count` (`meshop.getNumMapVerts`), `min` and `max`: `[u, v, w]` over the map vertices the map faces use (`null` when they use none). Count and range cannot show a U running the wrong way along a spline; `eval_maps` has every corner, for a UVW Map only. |
| `modifiers` | The modifier stack from top to bottom (modifier_pivot: a Bend added over a UVW Map lists Bend first), each: `class_id`, `class_name`; `name` (`m.name`: the one the user gave, else the class's display name); `enabled`, `enabled_in_views`, `enabled_in_renders`; `context_tm` (`getModContextTM`, 12 floats as `transform`) and `context_bbox_min`, `context_bbox_max` (`getModContextBBoxMin/Max`): the modifier context on this node, which an instanced modifier has once per node. The box is the one Max holds after evaluating the node; the file may hold none (docs/FORMAT.md, Modifiers). |
| `instances` | Sorted handles of every node that shares this node's base object, itself included (a one-element list when not instanced). Instances and references both count. |
| `transform` | World node transform (`node.transform`, the pivot), 12 floats: rows 1 to 4, row 4 = translation. |
| `offset_pos`, `offset_rot`, `offset_scale` | Object offset: where the object sits relative to the pivot. `offset_rot` is a quaternion `[x, y, z, w]` as MAXScript gives it, which is the conjugate of the usual right-handed one: a rotation of +30° about Z (row 1 = `[0.866, 0.5, 0]`) prints as `[0, 0, -0.258819, 0.965926]`. Negate x, y and z before using it as a standard quaternion. Shown by modifier_pivot: FixtureBent's pivot alone turned +30° about Z gives an offset of -30°, `[0, 0, 0.258819, 0.965926]` (`tests/test_oracle.py`). |
| `object_transform` | World transform of the object (`node.objectTransform` = offset times node transform), 12 floats. Mesh vertices in object space times this matrix are world positions. |
| `camera` | `null` unless the base object is a camera (superclass 32). Then 3ds Max's camera state at frame 0 (`CameraObject::EvalCameraState`, through the SDK's .NET wrapper): `fov` the horizontal field of view in degrees that 3ds Max and V-Ray render with (after zoom, lens breathing and a specified FOV), `ortho`, `hither` and `yon` (the clipping planes, in file units), `manual_clip`, `tdist` (the target distance; 0 on a Target camera, whose distance is its target's). A lens shift (Physical, VRayPhysicalCamera) changes the state's FOV but not the rendered one (renders of a marker scene show the image only translated): the state is read with `horizontal_shift` and `vertical_shift` at 0, then they are put back. |
| `bbox_min`, `bbox_max` | World-aligned bounding box of the evaluated object: `nodeGetBoundingBox node (matrix3 1)`. This is the tight box of the evaluated points (checked against the vertex extremes of a rotated, bent, parented sphere); `node.min` / `node.max` would instead transform the object's local box and be larger under rotation. |
| `layer` | Name of the node's layer. |
| `hidden`, `frozen`, `renderable` | The node's own flags (a layer's flags are in `layers`): `INode.IsObjectHidden` and `IsObjectFrozen` through the SDK's .NET wrapper, `renderable` from MAXScript. MAXScript's `isHidden` and `isFrozen` also answer true for a node on a hidden or frozen layer (layers_more: FixtureOnHiddenLayer, FixtureOnFrozenLayer), which version 6 wrote; the file keeps that state on the layer only (docs/FORMAT.md, Nodes). |
| `material` | Index into `materials`, `null` without a material. Max materials have no handle that survives a reload. |
| `shape` | `null` unless the base object is a shape (superclass 64). Then the base object as 3ds Max's own Bezier: a copy of the node without its modifiers, collapsed to an Editable Spline (`convertToSplineShape`). `splines`, each `closed` and its `knots`: `type` (`corner`, `smooth`, `bezier`, `bezierCorner`), `segment` (`curve` or `line`, the segment that starts at the knot; `null` after the last knot of an open spline), `pos`, `in`, `out` (`getKnotPoint`, `getInVec`, `getOutVec`, turned from world into object space by the inverse object transform) and `mid` (`interpBezier3D` at 0.5: the middle of that segment as 3ds Max interpolates it, `null` where `segment` is). The base object's `steps`, `optimize`, `adaptive`, and its rendering settings: `renderable` (Enable In Renderer), `display_render_mesh` (Enable In Viewport), `thickness`, `sides`, `angle`, `rectangular`, `width`, `length`. |

## The material graph

`material_graph` lists every material and map reachable from a node's material, each once, depth first from the
node materials in their order: an entry, then its sub-materials, its sub-maps, then every material or map one of
its properties holds (`getSubMtl` of a Multi/Sub-Object answers by material ID and skips some, its
`materialList` does not). MAXScript names parameters but never gives their ids, so the parameters are read through
3ds Max's .NET wrapper of the SDK (`Autodesk.Max`): `IParamBlock2.IndextoID`, `GetParamDef` and the typed getters
at time 0. Values are as stored: angles in radians, fractions as fractions, colors as floats 0..1, not the degrees,
percentages and 0..255 colors MAXScript shows.

| Key | Value |
|---|---|
| `index` | Position in `material_graph`. |
| `name`, `class_id`, `class_name` | As in `materials`. |
| `superclass` | 3072 (material) or 3088 (map). |
| `blocks` | The parameter blocks among the entry's references, in reference order. |
| `parts` | The references that are neither a block nor a material or map but carry blocks of their own: a map's coordinates (UVGen, XYZGen) and output, a Standard material's shader and sampler. `ref` (reference slot), `class_id`, `blocks`. |
| `subs` | The sub-materials and sub-maps that are set: `kind` (`material` or `map`), `slot` (0-based, as `getSubMtl` / `getSubTexmap` count), `target` (index into `material_graph`). |

A block: `kind` `pb2` (ParamBlock2) or `pb1` (the old ParamBlock), `ref` (its reference slot in the entry or
part), `block_id` (the ParamBlock2's descriptor id, `null` for `pb1`), `controllers` and `params`.

`controllers`: one entry per animated parameter of a `pb2` (per element of an animated table), in parameter order:
`id`, `tab` (the element, 0 for a scalar), `class_id` (the controller's, `IParamBlock2.GetControllerByID`), `slot`
(the block's reference slot that holds the controller, found by comparing `GetReference` with it; -1 if none
does), `value` (the parameter's value at frame 0, as in `params`). Always empty for `pb1`: its controllers are
not dumped.

`params`:

- `pb2`: every parameter of the descriptor in its order: `id`, `name` (its internal name, may be empty), `type`
  (the SDK's ParamType2, `0x800` added for a table), `transient` (not saved in the file), `value`. A table's value
  is a list of its elements.
- `pb1`: `index`, `type` (ParamType: 0 float, 1 int, 2 color, 3 point3, 4 bool), `value`.

Values by type: numbers for float, angle, percentage, world and color-channel parameters and for int, bool,
time, radio-button and index parameters; `[r, g, b]` for colors, `[r, g, b, a]` for float colors with alpha,
`[x, y, z]`, `[x, y, z, w]`, `[x, y]` for points; text for strings; the base name for a file name; the
`material_graph` index (or `null`) for a material or map parameter; `null` for every other type (node,
reference target, bitmap, matrix).

## Measured

- The 22 fixtures before stack_basic, 2026-11-17: under 0.4 s each to load, under 0.7 s to dump (vray_texmaps, the slowest, 0.64 s).
- Scene A (746 nodes) and scene B (2,251 nodes), 3ds Max 2020, 2026-11-15: A loaded in 10 to 50 s (warm or cold
  disk cache) and dumped in 5 s, B loaded in 5 s and dumped in 17 s; the Max process peaked at 3.1 GB. Their dumps are kept outside the
  repository.
