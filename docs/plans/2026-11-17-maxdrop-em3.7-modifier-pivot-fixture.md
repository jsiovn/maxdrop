# Fixture with a modifier stack and a rotated pivot Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Data, not docs, for three things every committed oracle left unshown: the order of a node's modifier
list (top to bottom), the evaluated counts after a modifier, and the sign of the stored object offset rotation.

**Architecture:** One new self-authored fixture (`tools/fixtures/modifier_pivot.ms` -> `tests/fixtures/
modifier_pivot.max` + its oracle). No reader or convert change: the existing reader tests that assumed "no
modifier, identity offset rotation" in every fixture are generalised to compare with the oracle instead.

**Tech Stack:** 3ds Max 2020 through the 3dsmax-mcp bridge (own instance), plain Python unittest, Blender 4.2 /
4.5 / 5.2 headless.

---

## The fixture

One Editable Poly box 10 x 10 x 40, four height segments (20 vertices, 18 quads), Standard material, three nodes
on one base object:

- FixtureSource: the bare base object.
- FixtureBent: a **reference** with UVW Map, then Bend (60°) on top; its pivot alone turned +30° about Z
  (Affect Pivot Only: node turned, object offset turned back), so the offset rotation is -30°.
- FixtureSmooth: a reference with TurboSmooth (1 iteration): eval 74 vertices, 144 triangles.

References, not instances: in 3ds Max a modifier added to an instance goes to every instance (checked: two
instances both got all three modifiers). Saved with the gamma off and file gammas 2.2 like every fixture but
gamma_swatches (`tests/unit/test_gamma.py`).
