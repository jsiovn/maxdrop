# Camera exposure and depth of field in build Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The build side gives a camera its depth of field and the scene the scene camera's exposure from three new
CameraDescription slots, so that maxdrop-o53.3.1 only fills the numbers in.

**Architecture:** `convert/cameras.CameraDescription` gains `exposure`, `dof_distance`, `fstop` (all None from
`describe()` in this bead). `build/cameras.make_camera` turns depth of field on from them and stores the exposure as
the custom property `maxdrop_exposure` on the Camera; `set_render` sets `scene.view_settings.exposure` to the scene
camera's exposure. `pipeline._Run` saves and restores the view exposure with the render size. `convert/report.gather`
names the applied exposure and the cameras whose exposure differs on the render line.

**Tech Stack:** Python 3.11, Blender 4.2 / 4.5 / 5.2 bpy, unittest.

Bead: maxdrop-o53.1.8. BASE: 80759242a925e873383005eef984db03141b9665.

---

## File Structure

- `maxdrop/convert/cameras.py`: the three slots only (constructor keywords, default None).
- `maxdrop/build/cameras.py`: `make_camera` depth of field + custom property; `set_render` view exposure.
- `maxdrop/pipeline.py`: `_Run.steps` saves `scene.view_settings.exposure` in `self._render`; `undo()` restores it.
- `maxdrop/convert/report.py`: `Report.exposure`, `Report.exposure_others`; `gather` fills them; `text()` appends them
  to the render line.
- `tests/unit/test_cameras.py`: slots default None, `describe` leaves them None.
- `tests/unit/test_report.py`: the render line with an applied exposure and a camera of another exposure.
- `tests/blender/nodes.py`: `_state()` includes the view exposure (every cancel check guards it).
- `tests/blender/checks_objects.py`: `check_camera` also checks no `maxdrop_exposure` on the fixtures' cameras;
  new `check_camera_settings(cameras_max, no_camera_max)` with hand-made descriptions.
- `tests/blender/suite.py`: registers `check_camera_settings`.

## Decisions

- The scene camera's description is the one whose `users` holds `desc.camera` (users are node indices).
- A camera "differs" when its `exposure != ` the scene camera's (None counts as "none"); compared only between
  descriptions, so instances of one camera count once. Named by `CameraDescription.name`, cut with `_names`.
- Render line suffix: `"; exposure: %g"` when applied, `"; other cameras' exposures, not applied: Cam2 0.5, Cam3 none"`
  when any differ. Nothing is added when no camera has an exposure (all fixtures today: their lines are unchanged).
- `aperture_fstop` is set only when `fstop` is not None (Blender's default stays otherwise).
- No CHANGELOG line: nothing a user sees changes until maxdrop-o53.3.1 fills the slots (that bead adds it).
  docs/SUPPORT.md and docs/FORMAT.md stay true ("exposure is left out").
