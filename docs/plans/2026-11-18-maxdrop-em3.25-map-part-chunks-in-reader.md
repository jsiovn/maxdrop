# Map part chunks in reader/ Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `convert/texmaps.py` takes parsed Placement, Output and BitmapInfo values from `reader/materials.py`
instead of reading chunk ids itself; the duplicated value helpers of `convert/texmaps.py` and
`convert/materials.py` live in one place. Bead: maxdrop-em3.25. No behavior change.

**Architecture:** Three module functions in `reader/materials.py` own the chunk ids and bit layouts:
`placement(scene, index)` -> `Placement` namedtuple, `output_invert(scene, index)` -> bool and
`bitmap_gamma(scene, m)` -> the stored override gamma or None. They take the scene (anything with `chunk(i)`)
rather than becoming fields of `MtlBase` / `Part`: `tests/unit/test_texmaps.py` must pass unchanged, and its
fakes build `Part` with five fields and hand Placement / BitmapInfo chunks through a fake `scene.chunk()`.
Policy stays in convert: range checks of axis, source and channel, vertex color -> channel 0, the usable gamma
range 0.1..10. New `convert/params.py` holds `finite`, `num`, `flag` (`materials.py` imports `texmaps.py`, so
texmaps cannot import them from materials).

**Tech Stack:** plain Python 3.9+ (tests) / 3.11 (Blender); unittest.
