# VRayMtl Fresnel-off metal rule under a reflection map Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The VRayMtl metal rule (reflection Fresnel off, bright reflection) judges the reflection V-Ray shows,
not a swatch a reflection map at full amount hides.

**Architecture:** `convert/materials.py` `vray_mtl`: V-Ray's map slot blends the swatch and the map by the
multiplier (`lerp(swatch, map, amount)`; above 100 the map alone, multiplied). The swatch's visible share is
`mean(reflection) * (1 - min(1, amount))`; the metal rule uses that share. A map at full amount (the classic
Fresnel-like Falloff) therefore never makes a metal: a dielectric whose specular follows the map, base color the
diffuse. The map itself is not judged: convert/ cannot evaluate a map's brightness (a bitmap, a Falloff's angle
ramp), and a black -> white Falloff is the dielectric setup by intent.

**Tech Stack:** plain Python (convert/ is bpy-free), unittest.

**Decision (no V-Ray render in this lane):** V-Ray's documentation of the texmap slots: the multiplier mixes the
swatch with the map; at 100 the swatch has no effect. With Fresnel off, the reflection color (or map) is the
reflection amount at every angle; a black -> white Falloff makes it rise to grazing, which reads as a dielectric
with Fresnel. What a render would still confirm: that a bright map (not a Falloff) at full amount over Fresnel off
looks closer to Blender's dielectric with that specular than to a metal (a bright reflection bitmap made to look
metal now loses metallic 1).

**Deviation:** the bead names `tests/unit/test_materials.py` (reader tests); the VRayMtl rule's tests live in
`tests/unit/test_convert_materials.py`, so the new test goes beside `test_fresnel_off_bright_reflection_is_metal`.
