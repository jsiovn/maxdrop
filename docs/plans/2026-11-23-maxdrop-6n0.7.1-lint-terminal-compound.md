# Lint: follow compound statements that always exit Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the unreachable-code check of `tools/lint.py` also reports the statement after a compound statement that
never falls through (a `with` whose body exits, an `if`/`else` exiting on both branches, a `try` whose body and
handlers exit), so a test def nested after such a helper (the maxdrop-em3.111 failure mode) cannot drop out unseen.

**Architecture:** one recursive predicate `_exits(stmt)` beside `_TERMINAL`; `unreachable()` asks it instead of
`isinstance(before, _TERMINAL)`. Standard library only, Python 3.9 and later (`ast.Match` 3.10, `ast.TryStar` 3.11:
looked up with `getattr`).

**Tech Stack:** Python standard library (`ast`), ruff 0.17.5 through `tools/lint.py`.

Bead: maxdrop-6n0.7.1

## Rule

A block (statement list) *exits* when any statement in it exits: control never reaches past that statement. A
statement exits when it is:

- `return`, `raise`, `continue`, `break`;
- `with` / `async with` whose body exits;
- `if` with a non-empty `else` where body and `else` both exit (`elif` is an `if` in `orelse`: recursion);
- `try` / `try*` whose `finally` exits, or whose handlers all exit and whose body or `else` exits (the `else` runs
  only when the body completes, so either one exiting covers the no-exception path; no handlers = `try`/`finally`);
- `match` whose last case is irrefutable (`case _:` / `case name:` without a guard, or an `|` holding one) and
  whose every case body exits.

Loops (`for`, `while`, async) never exit (a `break` leaves them; `while True` is not special-cased), nor do
function and class definitions. The finding is reported at the first statement after the exiting one, once per
block, as today; the message names the compound (`unreachable code after `with``, `if`, `try`, `match`,
`async with`).
