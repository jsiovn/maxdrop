# v0.1.0 gate: first open (maxdrop-0ah.5) Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the v0.1.0 promise on corpus scenes A and B (closed, textured, lit room at the right scale through
the scene camera, no traceback, no magenta, every approximation in the report), then set version 0.1.0 and make
the docs true for it. Not pushed.

**Architecture:** One committed check tool, `tools/first_open.py`, in the shape of `tools/baseline.py`: run with
plain Python it starts Blender headless (isolated profile) on itself; run inside Blender it imports the scene with
the operator's default options, renders one frame through `scene.camera` with EEVEE and writes a JSON of counts,
classes and yes / no checks (no scene, object or file name). The pure parts (pixel statistics, issue kinds, the
verdict) need no `bpy` and are unit-tested in `tests/test_first_open.py`. Images, logs and results stay in the
session scratch folder.

**Tech Stack:** Python 3.11 syntax, Blender 5.2 / 4.2.23 / 4.5.16 headless, EEVEE (engine id by version),
`scene.ray_cast`, `tools/baseline.py`, `zipfile` and WinRAR's `Rar.exe` for the pack check.

## Facts

- The operator's report object: `maxdrop.build.report.publish(rep)` receives the `convert.report.Report` of every
  imported scene; the tool wraps that function to keep `rep` (counters: placeholders, modifiers applied / converted /
  ignored, wrappers and maps peeled, maps unsupported, grey materials, sockets skipped, textures missing, issues).
- Issue reasons can quote object, map and file names (`%r`); the tool reduces each reason to a *kind* (quoted text ->
  `<name>`, numbers -> `N`, at most the first two `: `-separated parts) before it is written. The JSON is read by eye
  before anything goes into the bead notes.
- Light and camera nodes in the file: the base object's class entry has superclass `SC_LIGHT` (0x30) /
  `SC_CAMERA` (0x20) (`reader.scene.Scene.entry`). Each such node must be a Blender light / camera, a placeholder of
  its class, or an issue `light: not built` / `camera: not built`.
- Modifier stacks: `Scene.object_stack(node.object).modifiers` (reader); every class on a node must be counted under
  applied, converted or ignored in the report.
- The factory-startup World has a grey background (0.05): the gate render sets the world's strength to 0 so a lit
  image proves the imported lights work.
- Default operator options: Units = Auto, materials and UVs on, modifiers kept, Light Strength 1.43.
- tpr.5 (pack owner checks) is closed: no pack checks left to forward.

## Chunk 1: The check tool

### Task 1: pure functions, test first

- [ ] `tests/test_first_open.py` loads `tools/first_open.py` by path (no bpy) and tests:
  - `image_stats(pixels, width, height)` on flat RGBA lists: an all-black image -> mean 0, lit share 0; a
    half-magenta image -> magenta share 0.5; a purple-grey pixel (0.5, 0.4, 0.5) is not magenta; luminance by
    Rec. 709 weights.
  - `issue_kind("VRayBitmap 'wall.jpg': multiplier 2.5 not converted: 1")` ->
    `"VRayBitmap <name>: multiplier N not converted"`; a reason without quotes keeps its words.
  - `verdict(result)`: each of the five gate answers (`traceback`, `magenta`, `lit`, `closed`, `scale`, plus
    `report_complete`) from a result dict; thresholds as constants (`MAGENTA_MAX = 0.001`, `LIT_MEAN_MIN = 0.02`,
    `CLOSED_MIN = 0.9` per quadrant, `HEIGHT = (2.2, 4.5)`).
  - `read_log(path)` finds `Traceback (most recent call last)`.
- [ ] Run `python -I -m unittest tests.test_first_open` -> fails (no tool), then write the functions -> passes.

### Task 2: the Blender side

- [ ] `inside(root, path, out_json, png)`: register the dev package, empty the scene, wrap `build.report.publish`,
  `bpy.ops.import_scene.maxdrop(filepath=path)`, then:
  - counts: objects by type, materials, images, images whose file is missing (not packed, not on disk);
  - report counters (classes and counts) and issue kinds;
  - accounting: nodes vs objects built; light / camera nodes of the file vs built + placeholders + not-built
    issues; modifier classes per node vs applied + converted + ignored;
  - camera: `scene.camera` set; rays through a 16 x 16 grid per quadrant of `camera.view_frame` -> hit share per
    quadrant (`scene.ray_cast`, 1 km); vertical rays up and down from the camera -> room height;
  - render: EEVEE (`BLENDER_EEVEE_NEXT` on 4.x), world strength 0, 16 samples, the file's aspect with the long side
    640 px, write `png`; load it back, `image_stats`.
- [ ] Launcher `main()`: `--blender --profile --label --out <dir> <file>`; runs Blender with
  `--python tools/first_open.py -- inside ...`, log to `<out>/<label>-<blender>.log`, adds `traceback` from the
  log, prints and writes the JSON with `verdict`, exit 0 when every automated check says yes.
- [ ] Fixture run on 5.2 (`tests/fixtures/` file with a camera if any, else the local fixture: tool must finish
  and say "no camera").
- [ ] Commit `Add tools/first_open.py, the first-open check of a scene`.
