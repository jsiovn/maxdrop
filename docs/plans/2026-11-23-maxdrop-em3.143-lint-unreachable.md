# Lint: flag unreachable code Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `python -I tools/lint.py` fails on a statement after `return`, `raise`, `continue` or `break` in the same
block, so a test method left nested after a return (maxdrop-em3.111) cannot drop out of the suite unseen.

**Architecture:** ruff 0.17.5 (pyproject's `required-version`) has no unreachable-code rule: `ruff rule PLW0101`
says the rule does not exist, and `ruff check --isolated --select ALL --preview` on a probe (a def after a return
inside a class, a print after a return) reports nothing for the dead code. So the check is a small standard-library
AST pass in `tools/lint.py`, run after `ruff check` on the files ruff itself checks (`ruff check <args>
--show-files`, so excludes and `.gitignore` match). CI already runs `tools/lint.py`; no workflow change.

**Tech Stack:** Python standard library (`ast`), ruff 0.17.5 through `tools/lint.py`.

Bead: maxdrop-em3.143

## Rule

A statement that follows `return`, `raise`, `continue` or `break` in the same statement list (`body`, `orelse`,
`finalbody`, an `except` body, a `case` body) is reported once per list, at the first dead statement. No flow
analysis (an `if`/`else` that returns on both branches is not followed), no suppression comment: the tree has no
finding. Known limit (into the close note): a test def nested inside a helper that does not end in a terminal
statement stays unseen.
