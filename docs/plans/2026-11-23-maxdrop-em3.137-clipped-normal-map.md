# maxdrop-em3.137: a clipped normal map outside the image

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** settle what the area outside a clipped Bitmap gives under a normal map, keep MaxDrop's drawing if 3ds Max
agrees, and pin it.

**Architecture:** measured in 3ds Max first (below). 3ds Max renders the outside exactly as a black normal image, so
`maxdrop/build/materials.py` keeps its black there (the CLIP extension when nothing repeats, the clip mask of
`masked()` otherwise): only its docstring says why. `tests/blender/run.py` gains a check that a clipped normal map's
Normal Map node reads the image black outside, never mixed toward a flat (0.5, 0.5, 1).

**Tech Stack:** 3ds Max 2020 + V-Ray 5.2 / scanline batch renders (3dsmaxbatch), Blender 4.2 / 4.5 / 5.2 headless.

---

## Measurement (done before the plan; scene, images and renders outside the repo)

3dsmaxbatch, self-authored scene, gamma off: 40 x 40 planes under a top camera (600 x 600 px, 3 px per unit), lit
only by a directional light from +X at 45 degrees (no shadows, no GI, ambient black). Material: white diffuse, no
reflection (VRayMtl, bump multiplier 100 / Standard, specular level 0, bump amount 100); its bump slot a Normal Bump
(VRayNormalMap for V) whose normal map is a Bitmap of one color: FLAT (128, 128, 255), TILT (200, 128, 200), BLACK
(0, 0, 0). Pixels at each plane's center (`in`, inside the image) and 16 units out toward a corner (`out`), along U
(`outU`) and along V (`outV`).

Pass 1, clipped images (tiling 2, tile off: the image covers the plane's middle half):

| case | plane x, y | V-Ray 5.2 in / out / outU / outV | scanline in / out / outU / outV |
|---|---|---|---|
| C control, no bump map | -75, 25 | 180 / 180 / 180 / 180 | 180 / 180 / 180 / 180 |
| F FLAT, both axes clip | -25, 25 | 181 / 43 / 44 / 57 | 180 / 0 / 0 / 0 |
| T TILT, both axes clip | 25, 25 | 248 / 1 / 3 / 14 | 254 / 0 / 0 / 0 |
| U FLAT, U clips, V tiles | 75, 25 | 181 / 0 / 0 / 181 | 180 / 0 / 0 / 180 |
| P FLAT, tiling 1, crop placed 0.25..0.75 | -75, -25 | 181 / 77 / 72 / 86 | 180 / 0 / 0 / 0 |
| V VRayNormalMap over FLAT, both clip | -25, -25 | 181 / 42 / 39 / 54 | - |

Pass 2, the same places, each plane fully covered by BLACK (tiling 1, tile on):

| case | V-Ray 5.2 in / out / outU / outV | scanline |
|---|---|---|
| kF (F's place) | 57 / 43 / 44 / 57 | 0 everywhere |
| kT (T's place) | 15 / 1 / 3 / 14 | 0 everywhere |
| kU (U's place) | 0 / 0 / 0 / 0 | 0 everywhere |
| kP (P's place) | 81 / 77 / 72 / 86 | 0 everywhere |
| kV (V's place, VRayNormalMap) | 51 / 42 / 39 / 54 | - |

Reading: inside, FLAT equals the control (the normal map is wired at full amount, gamma plays no part) and TILT
differs (it acts). Outside the image every case is dark, not the control's 180: skewed, not flat. Every outside
pixel equals the fully black plane's pixel at the same place, in V-Ray and in scanline: outside the image the normal
map reads black, exactly. The V-Ray rows F, T, P and V carry that "exactly" (their value changes with the place
and matches the black plane at every sample point); scanline's 0 and V-Ray's U row (0 against 0) show only "dark,
not flat", since any normal facing away from the light clamps to 0. V-Ray's dark value varies with the place (0 to 86 here: its normal pointing into the
surface is shaded by view and light direction); F and T differ only by their x, not by their image.

## Decision

- No change to what is drawn: the black outside (the CLIP extension, or the clip mask under EXTEND) is what 3ds Max
  renders. The bead's "if flat" branch does not apply.
- `maxdrop/build/materials.py`: one sentence in the module's placement paragraph (functions part E owns), with the
  bead id. Blender's shading of that black normal is not compared pixel by pixel with V-Ray's: the record says
  "black, as in 3ds Max", not "the same pixels".
- No CHANGELOG or SUPPORT line: nothing a user sees changes. No FORMAT.md line: it is not a file-format fact, and
  the plan holds the measurement.
