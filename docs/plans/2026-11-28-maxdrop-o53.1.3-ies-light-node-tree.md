# IES profile in Blender: a light node tree with an IES Texture — Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A light whose description has a profile (maxdrop-o53.1.2) becomes a point light with an IES Texture node
(internal Text of the profile's text) into its Emission's Strength, with the watts of docs/FORMAT.md's measured rules
(maxdrop-o53.1.9); one Text per file per build; a failed build and a cancelled run leave no Text.

**Architecture:** convert/lights/families.py decides kind and power (no bpy): a profile light is POINT, its power
`s x IES_WATTS / ballast_lamp` (IES_WATTS = 4 pi / (683 x 0.070665) = 0.2604 W; s = the VRayIES's rendered lumens /
the file's flux, or for a web light its cd / the file's peak, provisional); its issue line reworded one for one, with
the upward share inside it. build/lights.make_light builds the node tree through `compat.light_nodes`, divides by
`compat.ies_gain(horizontal)` (4.x's measured plane-layout gain), and reuses Texts through a cache dict that
build/objects.Built owns. pipeline._remove removes new Texts unconditionally (a new Text has a fake user).

**Tech Stack:** Python 3.11, Blender bpy 4.2 / 4.5 / 5.2, unittest.

Base: `ba290cd`. Probe done (bead notes): Text users 1 + fake user on new; CRLF kept, NUL cuts; Cycles parses the
text cut at the last candela (5.2 0.04656 vs 0.04660 wanted; 4.2 x1.0835 at the nadir).
