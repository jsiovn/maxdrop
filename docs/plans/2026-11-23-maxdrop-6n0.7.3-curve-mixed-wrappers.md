# Curve mixed-ID line: wrappers that draw the same material — Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `MaterialConverter.source_for` answers a wrapper `peel()` has not walked yet with the material its peel
would reach, so a curve spline mixing two IDs whose entries are different wrappers around one base (or a wrapper and
its base) gets no "spline N mixes material IDs" report line. Bead: maxdrop-6n0.7.3.

**Architecture:** inside `source_for` only, replace the cache lookup `self._peels.get(i, (i, None))[0]` with a
local, non-counting copy of `peel()`'s walk: a cached peel answers at once; otherwise walk from `i` over `_sub` as it
is (same stop test as `peel()`: not a material, not a wrapper, or a CoronaLayeredMtl that mixes layers), at most
`MAX_PEEL` wrappers, a cycle guard on the chain, a `ChunkError` or a failed `_sub` -> `None`. It writes nothing
(`_peels`, `_counted`, `stats.peeled` untouched). A `None` base keeps the old answer, the wrapper itself (its grey IR
is its own). The walk starts from `i` like `peel(i)`, so it gives exactly `peel(i)[0]` (the depth guard counts from
the same object). `_sub`, `peel()`, `WRAPPER_SWITCHES`, `_mixed` unchanged.

**Tech Stack:** Python 3.11, plain unittest (no Blender for the unit tests), Blender 4.2 / 4.5 / 5.2 smokes.
