# VRayLight: dome light to World, mesh light, scaled sphere Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VRayLight dome becomes the scene's World (color or a spherical texture, calibrated strength, hemisphere,
orientation, ray visibility); a mesh light stays an empty with a clearer report line; a scaled sphere light gets the
radius and flux V-Ray gives it.

**Architecture:** `convert/lights.py` (no bpy) reads the dome's extra parameters and makes a `DomeDescription`
(`describe_dome`); `convert/scene.py` keeps the dome node an EMPTY (not a placeholder, no "not built" line) and sets
`desc.dome` from the first dome that is on, with an issue on any other. `ops.py` converts the dome's texture map
(`TexmapConverter`, kind COLOR) and `convert/lights.py dome_texture()` turns the TextureGraphIR into a
`DomeTexture` (image, projection turn, mirror rule, amount) or the reason it is not used. `build/world.py` makes a
new World from it and assigns it to the scene; `ops.py` records the previous `scene.world` and puts it back when the
build fails or is cancelled, removes made worlds with the other datablocks (`_MADE`), and the report says the World
was replaced. Sphere lights: `area_scale` returns a sphere's X scale squared in every units mode (key), `describe`
applies it to the flux only in the area units and to the radius always (sqrt).

**Tech Stack:** Python 3.11 syntax; 3ds Max 2020 + V-Ray 5.2 through 3dsmax-mcp (own instance) for probes and the
fixture; Blender 4.2.23 / 4.5.16 / 5.2 headless.

## Measured (V-Ray 5.2 in 3ds Max 2020, scratch scenes, not committed; Blender 4.2.23, 4.5.16, 5.2)

- **Point radius in Blender:** a POINT light's `shadow_soft_size` does not follow its object's scale (a
  camera-visible light in Cycles: 0.48 m across at scale 1, 2, (1,2,1), (1,1,2); EEVEE penumbra unchanged by scale,
  changed by the radius) on all three versions.
- **Sphere under scale (V-Ray):** W/m²/sr sphere, white floor below: flux × 1 at (1,2,1), (1,1,2), (1,2,3); × 4 at
  (2,2,2) and (2,1.5,1). The visible sphere: diameter × 2 at (2,1,1), × 0.5 at (0.5,1,1), unchanged at (1,3,1),
  round (not an ellipsoid). V-Ray takes the X scale only: radius size0 × |X scale|, area × X².
- **Mesh light:** `mesh_source` (parameter 34) is a node reference. Set by script, V-Ray 5.2 emits that node's mesh
  as it is now, at the light node's transform (a 20 x 40 box through a Target camera looking down: the footprint
  follows the light's position and turn, the box made 60 wide afterwards emits 60 wide, the box's own position does
  not matter, the box deleted emits nothing). (A first probe through a Free camera read this wrong: its ortho frame
  was not the one set.) What a UI Pick mesh with Replace mesh on leaves is not known. Building the emitter (the mesh
  at the light, its strength over its area) is more than this bead: a report line naming the node, a debt bead for
  the emitter.
- **Dome parameters:** 27 `dome_spherical` (V-Ray 5.2 default on), 49 `texmap_locktodome` (default 0), 34
  `mesh_source`, the rest as the other types (7 color, 8 multiplier, 10 invisible, 12 units, 18/19 texmap (on),
  25/26/30 affect diffuse/specular/reflections, 38/39 temperature).
- **Dome strength:** white floor under a white dome of multiplier 1: units 0 → pixel 1.00018, 1 (lm) and 2
  (lm/m²/sr) → 0.00213024, 3 (W) and 4 (W/m²/sr) → 1.43109. Cycles: a white World of strength 1 → 1.00002. So
  radiance (W/m²/sr) per unit: default 1500 / (π 683), lm modes 0.00213024 / 1.43109 (1 / 671.8: 1.7 % above
  1 / 683), W modes 1; Blender strength = radiance × Light Strength (1.43 → default units 0.9997 of V-Ray).
- **Hemisphere:** dome_spherical off: a downward-facing white plane gets 0 (on: 1.0); the camera sees 0 below the
  horizon. The half follows the dome node's rotation (turned 180° about X: the lower half lit), not its position.
- **Texture:** replaces the color (a dome color of 255,64,64 leaves a white texel white); the multiplier and units
  scale it as the color. VRayBitmap spherical (mapType 2): u = 0.5 + φ / 2π + h / 360 (φ = atan2(y, x), h its
  horizontal rotation in degrees), v up = image top. Bitmap with environment spherical mapping (UVGen 0x9005 = 1,
  0x9009 = 1): u = 0.75 + φ / 2π, as a VRayBitmap with h = 90. Lock to dome 0: the world frame; 1: the dome node's
  rotation (turned 90° about Z, the texture turns with it). Blender's Environment Texture through a Mapping node
  (Vector, scale (1, −1, 1), rotation Z −h) on Texture Coordinate Generated gives the same texels as V-Ray at
  ±X, ±Y, ±20° (checked h = 0 and h = 90 on 5.2).

## Rules

- Dome → `DomeDescription`: name, node, color (light_color), strength (radiance per the table, × multiplier),
  hemisphere (not spherical), rotation (the node's world rotation, orthonormal; mirrored → an issue, its rotation
  part used), locked, texmap index (when on), camera = not invisible, diffuse = affect diffuse, glossy = affect
  specular or reflections (an issue when they differ, as for the other lights).
- First dome that is on wins; another dome (also an instance) → issue on its node "a second dome light: not
  imported (Blender has one World)"; a dome that is off → issue "off: not imported". Dome nodes are EMPTYs, not
  placeholders.
- Texture (dome_texture): the graph's root must be an Image (Bitmap with environment spherical mapping, or
  VRayBitmap mapType 2); another root class → the World keeps the color (issue); another projection → drawn as
  spherical (issue); VRayBitmap vertical or axial rotation ≠ 0, a flip, ground projection
  (ids 4, 36, 5, 6, 26 from a probe scene) → issue; image not found → color (issue); TexOutput amount
  multiplies the strength, invert / level / offset → issue; gamma other than automatic or 1 → issue (not applied).
- Build: World "<dome name>", Background(color or Environment Texture, strength × Light Strength); Generated →
  Mapping(Vector, rotation of the Max-frame dome-local direction) → Separate XYZ → Z > 0 → × strength for a
  hemisphere; Generated → Mapping(scale (1,−1,1), rotation R') → Environment Texture, R' = Rz(−h) F Rtex F with F =
  diag(1,−1,1), Rtex = (dome rotation⁻¹ if locked) × axis conversion⁻¹. Ray visibility through
  `World.cycles_visibility` where it exists (compat).
- Sphere: key scale = X scale² in every units mode; flux × scale in default / lm/m²/sr / W/m²/sr; radius ×
  sqrt(scale).
- Mesh light: still not built; reason "a mesh light is not imported yet" plus "(V-Ray emits the mesh of <node> at
  the light's place)" when parameter 34 names a node of the scene.
