# Per-fixture test tables: a check that every fixture is listed — Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a new `tests/fixtures/*.max` cannot pass the plain suite and still break the Blender fixture run
(bead `maxdrop-em3.39`).

**Architecture:** the two `UV_LAYERS` tables stay where they are: they are keyed differently (run.py by object
name with a `UVMap` default and extrude handled by `EXTRUDE_UV_LAYERS`; test_convert_scene.py by mesh name with
an empty default), so one shared table would change semantics. Instead a plain test (no numpy, no Blender) checks
that both tables and the fixture list have the same keys; run.py's table is read with `ast` (run.py imports
`bpy`). run.py checks the entry itself before the loop and fails with a named check instead of a `KeyError`.
`FLOORS` gets an entry for every fixture (each has a material graph, at least one Standard material: 125 values)
and a plain test that its keys equal the fixture list; the parity test asserts the entry instead of skipping.

**Tech Stack:** Python 3.11 `unittest`, `ast`; Blender 4.2 / 4.5 / 5.2 for run.py.
