# Modal import with progress and Esc to cancel Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An import started from the UI (popup after a drop, or the file browser) runs in steps with progress in the
status bar and the cursor, and Esc cancels it, removing everything the run made; scripts and tests stay synchronous.

**Architecture:** The pipeline after validation becomes a generator (`_Run.steps()`): unpack each pack, read each
scene (reader + scene description + material conversion, bpy-free), build it in small steps. The synchronous path
drains it inline (no thread), exactly as before. The interactive path hands the `_Run` to an internal modal operator
`maxdrop.import_progress` (invoked with `INVOKE_DEFAULT` from `execute()`, the pattern `_reopen()` already uses) that
advances it on a timer within a time slice; the bpy-free phases (unpack, read) run in a worker thread there. Esc =
`generator.close()`: the `GeneratorExit` runs the existing `except BaseException: _remove(...)` cleanup of the scene
being built, then the run removes the scenes it finished and restores the scene camera and render size.

**Tech Stack:** Blender Python API (4.2 / 4.5 / 5.2), `threading` (bpy-free work only), `maxdrop.intake.archive`.

---

## Findings that shape the plan

- Scene B (headless, 5.2): `Scene.from_file` 0.24 s, `convert.scene.describe` 8.8 s, material conversion 0.65 s,
  `build.objects.build` 6.7 s, 16.7 s in all. `describe()` is monolithic and `convert/` is not in this bead's Files:
  the read phase runs in a worker thread (the bead allows reader work in a thread that shares no Blender data), the
  build is sliced.
- `archive.unpack()` has no progress or cancel hook, and the unpacker process is private to `external.run()`. The
  bead's addendum (2026-11-14) requires progress by bytes and "Esc ends the unpacker process and removes the staging
  folder", which ops.py alone cannot do. No open bead owns such a hook. Decision: a minimal hook in
  `maxdrop/intake/archive.py` (+ one call in `external.py`), mandated by the addendum, with a test in
  `tests/test_intake.py`; noted in the bead. The rest of intake is untouched.
  - `_Budget(limits, watch=None)`; `check_time(seen=None)` calls `watch(bytes)` (bytes = `seen` or `total`).
    `ZipBackend.extract` calls it per chunk (through `add`), the external watcher every 0.5 s (now passing its
    walk's total); `run()` kills the process when the watcher raises; `unpack()` removes staging on any exception.
  - `class Cancelled(PackError)`: zip's `except PackError: raise` keeps it unwrapped; `ExternalBackend.extract`
    only catches `ToolFailed`, so no next program is tried.
- Modal from `execute()` itself is what Blender's own `operator_modal_timer.py` template does, but our `execute()`
  is also called by the file selector's exec path, which this session cannot run (no windowed Blender). A second,
  internal operator invoked normally is the robust path; the outer operator returns `{'CANCELLED'}` after handing
  over (no empty undo step), the runner has `UNDO` and pushes one step when it finishes.
- `modal()` swallows every event but TIMER (stepped, then passed through for other timers' owners) and Esc: an undo,
  delete or file load mid-import would invalidate the datablock references the run holds.
- Seams pinned by tests: `tests/smoke_import.py` wraps `IMPORT_SCENE_OT_maxdrop._import_scene` and expects
  `(lines, rep)` (the sync path keeps calling it); `tests/blender/run.py` patches `ops._material_slots` (looked up
  at call time), patches `build_objects.build` to fail (the operator now calls `build_objects.build_steps`:
  `check_failed_build_cleanup` patches that instead, `build()` stays as a drain wrapper), counts one
  `AssetTable.from_file` per import; the register smoke wants `build` and `intake` unloaded at register (imports
  stay on demand).
- Cancel removes: objects, collections, meshes, curves, lights, cameras, materials, images made by the run (those
  that existed before stay), and a "MaxDrop Report" text the run created; the scene camera and render size are put
  back. A "MaxDrop Report" text that existed before keeps what the run wrote into it (the report of a finished file
  of the run). A finished pack folder on disk is never removed.

## File structure

- `maxdrop/intake/archive.py`: `Cancelled`, `_Budget.watch`, `unpack(..., watch=None)`.
- `maxdrop/intake/external.py`: the watcher passes its byte count to `check_time`.
- `maxdrop/build/objects.py`: `build_steps()` generator (yields `(done, total)`), `build()` drains it.
- `maxdrop/ops.py`: `ImportOptions` (a snapshot of the operator's settings), `_Run` (the step generator, cancel
  cleanup), `_scene_steps()` (one scene), `_read_scene()` (bpy-free read phase), `_in_thread()`,
  `MAXDROP_OT_import_progress` (modal runner), `execute()` splits validation from the run.
- `tests/blender/run.py`: `check_failed_build_cleanup` patches `build_steps`; new `check_cancel()` (step generator
  cancelled after N steps, one file and two files, also in the threaded mode; counts before = after).
- `tests/test_intake.py`: a watch that raises `Cancelled` mid-unpack: nothing left (no staging, no pack folder), a
  watch that only watches sees growing byte counts.
- `CHANGELOG.md`: Unreleased entry.
