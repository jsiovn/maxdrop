# TurboSmooth, MeshSmooth, Shell, Symmetry as Blender Modifiers Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Give TurboSmooth / MeshSmooth, Shell and Symmetry their Blender equivalent (Subdivision Surface,
Solidify, Mirror) on the imported object instead of ignoring them.

**Architecture:** `maxdrop/convert/modifiers.py` (no bpy) reads each modifier's ParamBlock2 by parameter id and
turns it into a `ModifierDescription` (Blender modifier type, settings, viewport / render switches, the mirror
frame). `convert/scene.py` converts the run of these modifiers that sits right above what MaxDrop evaluates (the base
mesh, an applied Extrude, applied UVW Maps), bottom first, into `node.converted`; the first other modifier stops the
run (an issue for each convertible modifier above it). The lowest smoother decides the mesh's shading: Smooth Result
clears the sharp edges and flat faces (the mesh key gains `("shading", "smooth")`), Separate by Smoothing Groups keeps
them and creases the sharp edges (`("shading", "crease")`). `build/modifiers.py` adds the Blender modifiers in order,
an empty as mirror object when the mirror plane is not the object's own, and the crease attribute. An operator
option "Modifiers: Keep as Blender Modifiers / Ignore" (default keep) passes `convert_modifiers` to `describe`.

**Tech Stack:** Python 3.11 syntax, standard library + numpy, unittest; 3ds Max 2020 via 3dsmax-mcp for the probe,
the fixture and the oracle; Blender 4.2 / 4.5 / 5.2 headless.

---

## What 3ds Max 2020 stores (probed on two scratch scenes, read back with reader/modifiers.py)

All four are object-space modifiers (superclass 0x810) with one ParamBlock2 in reference slot 0.

- TurboSmooth `(0x0D727B3E, 0x491D29A7)`: 0 iterations, 1 useRenderIterations, 2 renderIterations, 3 isoline
  display, 4 smoothResult, 5 sepByMats, 6 sepBySmGroups, 7 update (radio), 8 explicitNormals.
- MeshSmooth `(0x00000032, 0x00007F9E)`: 9 subdivMethod (0 classic, 1 quad output, 2 NURMS), 4 iterations, 2
  smoothness, 13 useRenderIterations, 14 renderIterations, 15 useRenderSmoothness, 16 renderSmoothness, 5
  smoothResult, 6 sepByMats, 7 sepBySmGroups. Vertex counts on a 20-unit box: NURMS / quad output follow
  Catmull-Clark (1 iteration: 26), classic does not (2 iterations: 80; Catmull-Clark gives 98).
- Shell `(0x3B9B1A16, 0x6D84E8D0)`: 0 innerAmount, 1 outerAmount, 2 overrideMatID, 3 matID, 4 overrideSmoothingGroup,
  5 smoothGroup, 6 edgeMapping, 7 tvOffset, 8 overrideInnerMatID, 9 matInnerID, 10-11 select, 12 segments, 13
  straightenCorners, 14 autosmooth, 15 autoSmoothAngle, 16 select, 17 overrideOuterMatID, 18 matOuterID, 19 bevel,
  20 bevelShape.
- Symmetry `(0x2D7E702B, 0x0BE41A6E)`: 0 axis (0 X, 1 Y, 2 Z), 1 slice, 2 weld, 3 threshold, 4 flip; the mirror
  gizmo is a PRS controller in reference slot 1 (`Modifier.gizmo`), `controllers.matrix` evaluates it.

## Conversion rules

- TurboSmooth, MeshSmooth -> `SUBSURF`, Catmull-Clark, `levels` = iterations, `render_levels` = render iterations
  when "use render iterations" is on, else iterations; `use_limit_surface` False (3ds Max places the refined control
  points, not the limit surface: checked against the oracle's box). Iterations outside 0 .. 10 are clamped (an
  issue). MeshSmooth classic -> Catmull-Clark (an issue: approximated), smoothness below 1 (an issue: not
  converted). Separate by materials: an issue (not converted).
- Shading of the mesh (decided by the lowest converted smoother): Separate by Smoothing Groups -> "crease" (sharp
  edges kept, `crease_edge` 1.0 on them, `use_creases`); else Smooth Result -> "smooth" (no sharp edge, no flat
  face); else unchanged.
- Shell -> `SOLIDIFY`: the new surfaces lie at -inner and +outer along the normal: `thickness` = (outer + inner) *
  meters, `offset` = (outer - inner) / (outer + inner), `use_even_offset` False (the oracle's box: 3ds Max moves along the vertex normals),
  `use_rim` True. A total of 0: not converted (an issue). Segments > 1, bevel, material-ID or smoothing overrides: an
  issue each (not converted).
- Symmetry -> `MIRROR`: `use_axis` only on the axis, `use_bisect_axis` = slice, `use_bisect_flip_axis` = flip (or its
  inverse, whichever matches the oracle), `use_mirror_merge` = weld, `merge_threshold` = threshold * meters. The
  mirror plane frame in the object's Blender space (offset baked, row vectors): E = gizmo * inverse(context) * offset;
  when E is not the identity, an empty (child of the object, `matrix_basis` = E in Blender convention, translation in
  meters) is the `mirror_object`.
- Only a modifier that renders is converted (as the applied ones); `show_viewport` = enabled in viewport.
- The run: bottom first, after the applied ones, every modifier is one of the four or the run ends; each of the four
  above the end is an issue ("modifiers: TurboSmooth above Edit Poly is not converted"). A modifier the rules refuse
  (unreadable block, animated parameter) ends the run too (an issue).
- With the option Ignore (`describe(..., convert_modifiers=False)`) nothing is converted and nothing is said about
  it: the modifiers count as ignored.

## Outcome

- Fixture stack_convert (9 nodes) and its oracle; Blender's evaluated meshes equal 3ds Max's counts and boxes on
  5.2, 4.2.23 and 4.5.16, but for two documented differences: FixtureOrder's seam, which 3ds Max leaves unwelded
  (100 vertices, Blender 84, the same box), and a vertex within Symmetry's weld threshold of the plane, which Blender
  merges onto the plane (FixtureSymmetryTurned: the box within the threshold). Measured: Subdivision with
  `use_limit_surface` off, Solidify with `use_even_offset` off, Blender's bisect flip = 3ds Max's flip.
- Code review: viewport levels are lowered when an object would pass about a million faces in the viewport
  (`budget`, an issue; render levels stay); Shell's amounts and Symmetry's threshold take the object offset's scale
  (an uneven one is an issue); the lowest smoother that changes the shading decides; a sheared mirror frame keeps
  its shear in the empty's parent inverse; the empty is frozen with its object and is not in `built.helpers`.
- tests/smoke_import.py learned the converted modifiers (its expected "not applied" counts and stack_convert's issue).
- Corpus (numbers only): scene A converts 1 of its 2 TurboSmooth (the other modifiers sit on a shape without an
  Extrude); scene B converts TurboSmooth on 105 nodes, MeshSmooth on 51 and Shell on 2; 6 TurboSmooth sit above an
  FFD(box).
