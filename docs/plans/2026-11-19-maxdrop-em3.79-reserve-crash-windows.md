# Unpack destinations never appear empty; a failed rename-back is kept — Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the crash windows of `maxdrop/intake/archive.py` that bead maxdrop-em3.79 names: (a) a crash
between creating a destination and writing its reservation file leaves an empty folder that keeps its name; (b) a
crash between creating the folder of a several-scene pack and its marker leaves a marker-less folder; (c) a folder
`_clear_stale_reservation` cannot rename back is removed later as stale staging.

**Architecture:** One helper creates a folder already filled: the content is written into a folder with a staging
name beside the target (`STAGING_PREFIX + "new-" + random`, made with `os.mkdir`, so the default permissions, not
mkdtemp's 0700), then renamed into place. `_rename_new(src, dst)` refuses an existing `dst`: Windows' rename does by
itself; POSIX rename replaces an empty folder and Python has no no-replace rename, so `dst` is looked at first (an
empty folder made in that instant is replaced: documented). `_reserve` writes the reservation file into such a
folder and renames it to the first free candidate (clearing a stale reservation as before); the pack folder of a
several-scene pack gets its marker the same way, with `_remove_stale_staging(dest_parent)` run first so a leftover
from a crash there is cleaned too. A rename refused while the target does not exist (Windows: a file held open)
falls back to the old mkdir + fill. `_clear_stale_reservation` still takes a folder aside under a staging name
(`STAGING_PREFIX + "reclaim-"`), so a crash or failure while a stale folder is removed leaves staging, cleaned
later; only a folder no longer stale whose rename back fails (name taken, or the rename refused) is renamed to a
distinct `RECLAIM_PREFIX` (`.maxdrop-reclaim-`), which stale-staging cleanup never matches. (Revised during
review: the first draft took the folder aside under `RECLAIM_PREFIX`, which would keep a stale folder for ever
after a crash mid-clear.)

**Tech Stack:** plain Python 3.11, unittest.
