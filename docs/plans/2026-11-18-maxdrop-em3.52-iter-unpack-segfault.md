# Plain suite segfault (struct.iter_unpack over a stream view) Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `python -I -m unittest discover tests` no longer crashes on Python 3.9 / 3.11 (Windows): the reader
leaves no buffer export of a stream view behind when a reference read fails.

**Architecture:** `Scene.ref_list` builds its list with a comprehension over `struct.iter_unpack("<i",
refs.view())`. On Python <= 3.11 a comprehension is its own frame and the iterator is its argument `.0`, so when
`_target` raises (a reference past the objects) the frame, kept by the exception's traceback, keeps an
unexhausted unpack iterator that holds a buffer export of the chunk's memoryview slice. When that traceback
ends up in a reference cycle, the garbage collector's `tp_clear` of the memoryview fails (`BufferError:
memoryview has 1 exported buffer`, printed as "Exception ignored in tp_clear"), drops its managed buffer anyway,
and the interpreter crashes later (access violation). Reproduced on the base commit `fc4f566` with
`test_malformed.py` alone (exit 139 on 3.9.13), and with a 20-line script on plain CPython 3.9 / 3.11 (no
MaxDrop, no numpy); 3.13 inlines comprehensions and does not crash. HEAD passes only because the GC timing moved.
Fix: unpack each reference payload into a tuple with `struct.unpack` / `unpack_from` (the buffer is released
before the call returns), so no iterator over a view outlives a raise. Same treatment for `Scene.refs`'
`_PAIR.iter_unpack` loop. Values returned are unchanged.

**Tech Stack:** plain Python 3.9-3.13, `struct`, `unittest`.
