# CoronaBitmap and CoronaColor HDR with the gamma off Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In a scene saved with the gamma off, draw a CoronaBitmap and a CoronaColor HDR color on a color input or a
mask the way Corona 12 shows them: their own value, decoded once more for the display-referred scene, as V-Ray does
for a VRayBitmap (maxdrop-em3.123).

**Architecture:** `convert/texmaps.py`: `_corona_image` applies `_shown` on COLOR and MASK with the gamma off and keeps
its own decode in STORED (as `_vray_image`); `_corona_color` decodes the HDR color (times its multiplier) with the
extended sRGB curve on COLOR (per channel) and MASK (the mean) with the gamma off, and keeps it as stored in STORED
(the Decode above shows it). `convert/lights.dome_texture` undoes `_shown` for a float CoronaBitmap as for the other
float dome textures. Data, normal and bump inputs, the gamma on and an unknown gamma are unchanged.

**Tech Stack:** Python 3.11 syntax, `unittest`; 3ds Max 2020 + Corona 12 (`3dsmaxbatch`) for the renders; Blender
4.2 / 4.5 / 5.2 headless.

So Corona holds a CoronaBitmap's own decode and the HDR color as V-Ray holds a VRayBitmap's and its maps', in both
modes, and the swatch as stored, which MaxDrop already decodes with the gamma off (the swatch rule is confirmed for
Corona). By the same logic the maps are decoded once more. Pass 1 gave the Bitmap automatic 128 0.2195 with the
gamma off (rendered to an EXR output file): not used; the CoronaBitmap and CoronaColor rows agree in all three
passes. A CoronaColor HDR color as a mask is assumed to follow the image mask (measured) and V-Ray's swatch mask.

## The rule (gamma off; COLOR and MASK kinds; DATA, NORMAL, BUMP, DATA_RGB, BUMP_RGB, gamma on and unknown unchanged)

- CoronaBitmap: `gamma = _shown(own)` where own is its gamma after `_auto_gamma` (automatic 8-bit None -> 5.0, Linear
  Rec.709 with a Gamma node; 1.0 or an automatic float file -> 2.2, sRGB, extended above 1 by Blender; 2.2 -> 4.84).
- In STORED (below a gamma-off Mix or Composite at a color root, maxdrop-em3.158): own decode kept (the Decode above
  shows it decoded once more), no longer divided by 2.2.
- CoronaColor HDR (method 1): rgb = max(0, c) x multiplier; COLOR: `srgb_to_linear` per channel (extended above 1);
  MASK: `srgb_to_linear(mean)`; STORED: the channels as stored (`_linear`'s STORED branch removed: STORED is in
  STORED_RGB); DATA and the rest unchanged (as stored).
- Dome: `lights.dome_texture` unshows a float CoronaBitmap too (drop `cid != CORONA_BITMAP`), so a float dome texture
  keeps its own decode whatever its class (maxdrop-em3.166's rule).
