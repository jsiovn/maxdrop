# IES type A/B ranges V-Ray reads otherwise Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `convert/ies.py _flux_ab` give the flux V-Ray 5.2 renders for the type A and B ranges measured in
this bead, refuse the ones whose render has no simple rule, and record the numbers in docs/FORMAT.md.

**Architecture:** `parse` reads the header and the table; `_flux_ab` integrates a type A or B table;
`Photometry.scale` is what a VRayIES power is multiplied by (`convert/lights.py _describe_ies`, unchanged: a scale
of 0 already gives `IES_DARK`). The renders change four rules (below).

**Tech Stack:** plain Python (convert/ never imports bpy), unittest; 3ds Max 2020 + V-Ray 5.2 (3dsmaxbatch) for the
measurements, self-authored files in a scratch folder outside the repo.

Bead: maxdrop-6n0.6.5 (part E, maxdrop-6n0.6). Owns `convert/ies.py` `_flux_ab`, `parse`'s type A/B branch,
`Photometry.scale`, the module docstring; not `_Numbers` / `_after_tilt`.

## Rules to implement

- H from -180 to 180 (types A and B): only -90..90 counts; the planes at +-90 interpolated linearly. Read.
- V from 0: no longer mirrored. Each vertical run is extended below 0 by its first segment, floored at 0 (for a
  constant run the same as the mirror). Read with 2 or 3 vertical angles, or when every run is constant; 4 or more
  with a run that is not constant: refused (V-Ray renders the lower half black where its own flux extends it).
- Type A with H from 0 to 90: flux 0 (V-Ray renders nothing), not refused: `IES_DARK`.
- `Photometry.scale` for rated lumens of 0 or below: 1 when the flux is above 0, 0 for a flux of 0 (V-Ray renders
  a table without light black: its loaded power is 0).
- Partial ranges (V not from -90 or 0 to 90; H not -90 / 0 / -180 to 90 / 180): stay refused; FORMAT.md says why.
