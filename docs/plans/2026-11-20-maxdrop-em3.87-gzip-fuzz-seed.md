# Fuzz a gzip-compressed .max stream Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The .max fuzz harness gets a seed whose Scene stream is gzip-compressed (3ds Max's "Compress on
Save"), mutates its deflate bytes and gzip framing instead of chunk structures, and so reaches `cfb._inflate`.

**Architecture:** No 3ds Max session in this batch (epic maxdrop-bci rule), so no new saved fixture: the harness
builds the seed itself, `box_poly_standard.max+gzip`, by rewriting `box_poly_standard.max`'s Scene stream in
place as hand-framed gzip members plus zero padding and setting the directory entry's size. `MaxSeed` takes
(name, raw bytes); a compressed stream is not chunk-walked and gets gzip mutation kinds from a seed-specific
kinds table, so the cases of every existing seed stay byte-identical.

**Tech Stack:** Python 3.11 standard library (`zlib`, `struct`, `random`), unittest.

---

## Facts this plan rests on

- Bead: maxdrop-em3.87. Epic maxdrop-bci: take the Scope path without 3ds Max (test-only gzip rewrite in the
  harness), no version bump, a CHANGELOG line only for user-visible changes (none here: tests only).
- `cfb.CompoundFile.open()` inflates a stream that starts with `1f 8b 08` (`_inflate`: members one after
  another, bytes after the last member that do not start a new one are padding, a 4 GiB output cap).
- Every fixture's Scene is one run of 4096-byte sectors; `box_poly_standard.max` Scene is 166,612 bytes and
  deflates to about 8.4 KB, so the compressed stream stays at 4096 bytes or more (below that the reader takes the
  mini stream).
- `fuzz.MaxSeed._walk` maps chunk offsets through raw runs: wrong for a compressed stream.
- Deflate output depends on the zlib build (1.2.12 here, other builds on CI): the gzip seed's bytes, and so its
  cases, replay per zlib build. No test asserts a compressed length, a digest or exact outcome counts for it.
- The 4 GiB cap cannot be reached under `fuzz.MEMORY_LIMIT` (1 GiB): it stays covered by `tests/unit/test_cfb.py`
  (`Gzip.test_size_cap`). The harness exercises large inflation only up to tens of MB.

## File Structure

- Modify `tests/unit/fuzz.py`: gzip seed builder, `MaxSeed(name, raw)`, gzip structure index, gzip mutation kinds,
  seed names through `seeds()`, `campaign`, `replay`; docstring.
- Modify `tests/unit/test_fuzz.py`: gzip seed tests, slice count over all seed names.

### Task 1: The gzip seed

**Files:** Modify `tests/unit/fuzz.py`

- [ ] `_gzip_member(data, level=9)`: `1f 8b 08 00` + mtime 0 + XFL 0 + OS 0 (hand-written: `gzip.compress`
      header bytes differ by Python version) + raw deflate (`zlib.compressobj(level, DEFLATED, -15)`) + CRC32 +
      ISIZE, little-endian.
- [ ] `gzip_scene(raw)`: split the Scene into 3 parts, one member each, 24 zero bytes of padding, padded further
      to at least 4096; write it over the start of the Scene's sectors (the chain keeps all its sectors, zeroed
      past the new size: room for mutations that grow the stream), set the directory entry's size (u64 at +120).
- [ ] `GZIP_SEEDS = ("box_poly_standard.max",)`, `GZIP_SUFFIX = "+gzip"`; `seed_names("max")` = fixture names +
      gzip names; `seeds("max", names)` builds `MaxSeed(name, raw)`; `campaign` and `replay` use them.

### Task 2: Gzip index and mutations

**Files:** Modify `tests/unit/fuzz.py`

- [ ] `MaxSeed`: for each stream whose raw open is `.compressed`: skip `_walk`; record its capacity runs (all
      sectors of its chain), its directory entry offset, its raw bytes and its members `(start, deflate start,
      deflate end, end)` parsed from the bytes (FLG extras honoured), plus the padding span.
- [ ] `seed.kinds`: `_KINDS` for a plain seed; `_KINDS[:-1] + _GZIP_KINDS + (("multi", 5),)` for a compressed
      one. `max_case` and `multi` draw from `seed.kinds` (identical draws for plain seeds).
- [ ] `_GZIP_KINDS`: `gz_flip` (bits in deflate bodies), `gz_header` (ID, CM, FLG bits FTEXT..reserved, MTIME,
      XFL, OS), `gz_trailer` (CRC32 / ISIZE to extremes or off by one), `gz_block` (BFINAL/BTYPE bits incl. the
      reserved type, bits of the first deflate bytes), `gz_boundary` (a later member's magic broken: silently
      shorter output; a gzip magic started in the padding), `gz_members` (a member dropped, duplicated, two
      swapped, garbage after the last), `gz_cut` (directory size cut inside a header, deflate, trailer, at a
      member end, or below 4096; or the tail zeroed), `gz_expand` (a member replaced by one inflating to 1-16 MB
      of one byte value, cached per process).

### Task 3: Tests

**Files:** Modify `tests/unit/test_fuzz.py`

- [ ] The unmutated gzip seed: Scene opens compressed, inflates to the fixture's Scene, reads `ok` through
      `fuzz._Reader`, and `describe()` gives the same description reprs (nodes, meshes, issues) as the fixture.
- [ ] Its index: at least 2 members, padding, no Scene chunk heads, ClassDirectory3 heads kept.
- [ ] Every gzip kind changes the file within 600 cases; cases are a function of (seed, k).
- [ ] Some gzip cases are refused by `_inflate` (`CfbError` "compressed stream ..."), not only by the CFB layer.
- [ ] Slice count: `CASES * len(fuzz.seed_names("max"))`.
