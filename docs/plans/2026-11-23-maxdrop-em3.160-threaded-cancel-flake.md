# Threaded cancel check without a race: implementation plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make `tests/blender/run.py`'s check "cancel: threaded, closed while the worker reads: nothing made"
deterministic (bead `maxdrop-em3.160`).

**Architecture:** the check takes one `next()` of `run.steps(threaded=True)` and wants `ops._WAIT`. `_in_thread`
starts the worker and yields `_WAIT` only while `worker.is_alive()`: on a loaded machine the worker can read the
small fixture to its end before that first check, the build starts and the first step is a build step, so the
check fails although nothing is wrong. The fix holds the worker in the read until `close()` asks it to stop:
the check swaps `ops._read_scene` (looked up as a module global by `_scene_steps` when the read starts) for a
wrapper that waits until its `cancel()` (the run's `stop.is_set`) holds, then calls the real read with that
cancel (which stops at its first check). The worker is alive at the first step by construction, `close()` sets
the stop event and joins it. The check also asserts that the wrapper ran and saw the cancel set (`saw ==
[True]`) and that no worker is left (`ops._busy() == ""`). A cancel in the middle of the real read is no longer
taken here; "read cancel" (check_read_cancel) covers it deterministically. `maxdrop/ops.py` is not changed (part E owns it).

**Tech Stack:** Blender Python (headless, isolated profile), `threading`.

with a block that patches `ops._read_scene` with `held_read(max_path, opts, dirs, cancel=None)`: polls

is ops._WAIT`, `steps.close()`; in `finally`: put `ops._read_scene` back and join every `ops._WORKERS` thread
(60 s). Check: `waited and saw == [True] and ops._busy() == "" and _state() == before`, with a detail string.
