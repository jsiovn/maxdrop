# Older files: pre-2013 code pages and more 3ds Max versions Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Names of files saved by 3ds Max 2012 and older (8-bit "ANSI" strings) read correctly, the user can pick
the code page, and the supported 3ds Max versions are backed by fixtures saved as 2017, 2018 and 2019.

**Architecture:** A new bpy-free `maxdrop/reader/strings.py` holds `Strings` (how one file's strings decode: wide
UTF-16LE, or 8-bit in a code page) and `of_file(cf, choice)` (the decision). The decision rides on
`chunks.Source`, so every `Chunk.text()` of a stream, the ParamBlock2 strings and the layer names decode the same
way without threading an argument through every reader. `Scene.from_file(cf, classes=None, encoding="AUTO")` makes
the decision and passes it to the class directory and the Scene index. The operator gets a "Text encoding" option.

**Tech Stack:** Python 3.11 stdlib (`codecs`), Blender 4.2 / 4.5 / 5.2, 3ds Max 2020 for the fixtures.

---

## Decisions

- Wide or 8-bit: the writer's version (`3ds Max Version` of DocumentSummaryInformation; 15 = 3ds Max 2013 and
  later write UTF-16). Not the saved-as version: corpus scene A, written by 3ds Max 2015 in the 2012 format, has
  UTF-16 names. Not the root container id: `0x2014` is the 2012 format, written by both. Below 15 or without a
  version: the DLL and class names vote (an 8-bit name ends with its only NUL; an ASCII UTF-16 name has a 0 second
  byte and an even size; others abstain); below 15 8-bit unless they say UTF-16, without a version UTF-16 unless
  they say 8-bit. (Revised after review: the first version let the names override the version, which could cut
  the names of a Unicode file with non-ASCII class names.)
- 8-bit strings: cut at the first NUL. Choice "AUTO": the code page the file's DocumentSummaryInformation (else
  SummaryInformation) records (property 1), when Python knows it and it is not 1200 (UTF-16, not an 8-bit page);
  else per string: strict UTF-8, else cp1252. An explicit choice decodes every 8-bit string with that code page
  (errors replaced). UTF-16 strings are never affected by the option.
- Layer name `0x1010` is UTF-8 in 3ds Max 2020 files: kept for wide files; an 8-bit file reads it as its other
  strings.
- ParamBlock2 STRING values: UTF-16 in wide files, 8-bit by the same rule in 8-bit files.
- Not changed: FileAssetMetaData strings (asset table, UTF-16 counts; an 8-bit file's layout is not known: Open in
  FORMAT.md), CFB directory names (UTF-16 by the CFB spec), the property-set strings (their own code page).
- Choices: AUTO, cp1252 (Western), cp1250 (Central European), cp1251 (Cyrillic), cp1253 (Greek), cp1254
  (Turkish), cp932 (Japanese), cp936 (Simplified Chinese), cp949 (Korean), cp950 (Traditional Chinese), utf-8.
- Pre-flight line: an 8-bit file adds "names in <code page>" so the user sees what Auto picked.
- Fixtures: `tools/fixtures/saved_as.ms` builds one scene (an Editable Poly box, a Standard material, a layer, with
  non-ASCII characters in the three names built from code points) and saves it as 2017, 2018 and 2019:
  `tests/fixtures/saved_as_2017.max`, `_2018`, `_2019`, each sanitized, checked, with its oracle. No pre-2013 file
  is available in this unattended session (the bead says "ask"): the 8-bit path is covered by synthetic chunks;
  the close note asks the owner for one.
