# LookAt Constraint animated weight: the slot rule measured on a fixture Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** lookat holds two LookAt Constraints with an animated target weight, saved by 3ds Max 2020, so the slot
rule maxdrop-em3.98 pinned on synthetic bytes (the weight's controller is the constraint block's next reference
slot, before the targets and the up node) is measured on a constraint and checked against the oracle.

**Architecture:** `tools/fixtures/lookat.ms` gets two boxes after its last node: FixtureWeightAnimated (targets
FixtureAim 50 and FixtureCam.Target 20, the second weight keyed to 90 at frame 50) and FixtureWeightUp (FixtureAim
60 keyed to 10 at frame 50, FixtureRig as an up node it looks at). The script runs in `3dsmaxbatch` through a
wrapper (ViewCube off, solid background) that also reports each constraint block's references and
`GetControllerByID`; the fixture is sanitized, checked, copied and its oracle dumped. `TestFixtures` compares the
two new nodes' matrices with the oracle; a new test class pins the block's slots on the saved bytes. No reader code
changes: the reader already matches.

**Tech Stack:** MAXScript (3ds Max 2020, `3dsmaxbatch.exe`), plain Python `unittest`, Blender 4.2.23 / 4.5.16 /
5.2 headless.

Bead: maxdrop-em3.156

## Facts measured (3ds Max 2020, `3dsmaxbatch`, probe outside the repo)

- FixtureWeightAnimated: block 0 NumRefs 4; `GetControllerByID 0 1` (the second weight) is a Bezier Float
  `(0x2007, 0)`, superclass `0x9003`, at reference slot 0; slot 1 FixtureAim, slot 2 FixtureCam.Target. The first
  weight stays a value (50). `weight` at frame 0 `#(50.0, 20.0)`, at 50 `#(50.0, 90.0)`. So the controller takes
  the next slot in entry order, not a slot per table element (the second element's controller is not at slot 1).
- FixtureWeightUp: block NumRefs 3; `GetControllerByID 0 0` a Bezier Float at slot 0; slot 1 FixtureAim, slot 2
  FixtureRig (`pickUpNode`). `weight` `#(60.0)` at 0, `#(10.0)` at 50.
- Without an animated weight (FixtureConstrained, FixtureConstrainedUp): the targets from slot 0, the up node
  after them (as before).
- The new oracle: the 22 existing nodes unchanged (every field), two nodes added at the end (indices 22, 23).
- The reader (unchanged) gives both new nodes the oracle's world and object matrices within 1e-4, no issue.
- The saved file is 864 256 bytes (was 581 632; under 1 MB); sanitize blanked 4 values; check_fixture clean.
