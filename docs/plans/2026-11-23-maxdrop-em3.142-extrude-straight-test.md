# Extrude straight-segment test Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `convert/extrude.py` calls a curve segment straight exactly when 3ds Max 2020's Optimize (and Adaptive)
does, so a Line drawn almost straight gets 3ds Max's point count (maxdrop-em3.142).

**Architecture:** `_straight(p0, c1, c2, p3)` is replaced by 3ds Max's test found by the probe below: the curve's
points at t 0.4 and 0.6 each turn the path p0 -> point -> p3 by at most 2 degrees (`ADAPTIVE_ANGLE`, the same
`_turn`). `_STRAIGHT` goes. `_polyline` keeps its callers (Optimize, Adaptive, the back-to-the-same-spot rule).

**Tech Stack:** plain Python (`tests/unit`), 3ds Max 2020 `3dsmaxbatch` for the probe (scratch, outside the repo),
Blender 4.2 / 4.5 / 5.2 headless for `tests/blender/run.py`.

## The probe (done, 2026-11-23)

Scratch MAXScript under `3dsmaxbatch` (outside the repo): open SplineShapes of two Bezier-corner knots with explicit
vectors, one curve segment, steps 6 (also 1, 3, 12), optimize on, under Extrude (1 segment, no caps); the points are
half the vertex count, read with the knots' float32 values. 3,359 segments in four runs:

| series (chord 10 unless said) | straight up to | curved from |
| --- | --- | --- |
| c1 off the chord by h at 1/3, c2 on it at 2/3 (chords 0.1 to 1000, any offset plane, far from the origin, steps 1 to 12) | h/L 10^-1.72 | 10^-1.70 |
| the same, c1 at 0.001 / 0.5 / 1.0 of the chord | 10^-1.82 / -1.70 / -1.78 | 10^-1.80 / -1.68 / -1.76 |
| both off by h, same side, at 1/3 and 2/3 | 10^-1.94 | 10^-1.92 |
| both off by h, opposite sides (an S) | 10^-1.24 | 10^-1.23 |
| collinear, c1 = a chords along, c2 at 2/3 | a 1.72 (and from -0.59) | a 1.74 (and from -0.60 down) |
| collinear, a = b (both past the far end) | 4.49 | 4.51 |
| collinear, c2 on p3 / on p0 / a chord behind p0 | a 1.2 / 2.1 / 0.8 .. 2.8 | 1.25 / 2.2 / below 0.7, from 2.9 |
| em3.111's square: Bezier knot at (10, -4), in vector (10 - d, -4), d 1e-3 .. 1e-6 | 11 columns for every d | |

Rule (no mismatch in any of the 3,359): at t = 0.4 and t = 0.6 the curve's point S turns the path p0 -> S -> p3
by at most 2 degrees (the angle between S - p0 and p3 - S; a leg of zero length turns nothing). Scale-invariant;
the collinear vectors past an end fold the curve back (180 degrees) once S passes an end.

Adaptive (optimize on and off, 30 segments): the same test decides which segments get no steps (all 30 agree). The
counts of a curved one follow a recursive split of the segment at its middle with this same test per piece, not
`_adaptive_steps`'s uniform depth (e.g. 5 steps where the uniform model gives 7, 3 where it gives 31), and deep
pieces stop by a rule not found (no depth cap fits all of a second probe). Not this bead: maxdrop-6n0.6.11 (part E,
P4, tech-debt) holds the probe numbers. Only the straight decision changes for Adaptive here.
