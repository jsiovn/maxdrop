# Stale reservation of an unpack destination Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A destination folder that `unpack()` reserved and never finished (Blender died between `os.mkdir` and
the pack marker) no longer blocks its name forever: a later unpack recognises it and takes the name again.

**Architecture:** `unpack()` writes a short-lived reservation file `RESERVATION` (`.maxdrop-reserved.json`,
distinct from `MARKER`) into the folder right after `_reserve` creates it, listing the names it is about to move
in (the maps and the scene). The marker is written last as before, then the reservation file is removed (best
effort: a failure there never undoes a complete folder). A folder is a *stale reservation* when it is a real
folder, holds no `MARKER`, holds a regular `RESERVATION` older than `_STALE_SECONDS` that parses and names the
scene, does not hold that scene, and holds nothing but `RESERVATION` and the maps it lists (by `name_key`).
`_probe` reports such a folder as "free" (so `preview()` and `_destination` agree with `unpack()`); `_reserve`,
when `os.mkdir` meets an existing folder, clears a stale reservation (the listed files, the reservation file
last, then `rmdir`) and creates the folder again; anything unexpected leaves it in place and takes the next name.
A crashed folder that already holds the `.max` keeps today's behaviour: it is used in place (a user may already
have imported from it, so it is never removed).

**Tech Stack:** Python 3.11 stdlib, unittest.

### Task 1: Tests for the crash case (red)

**Files:**
- Test: `tests/test_intake.py` (new class `Reservation` after `Race`)

- [ ] Helper `crash_after(n)`: patch `archive.os.rename` to raise a private exception after `n` moves and
  `archive.shutil.rmtree` to a no-op during that call, so nothing is cleaned up (a crash, not a failure).
- [ ] `test_a_crash_after_one_move_leaves_a_folder_a_later_unpack_takes_again`: pack with `room.max`,
  `wood.jpg`, `stone.png`; crash after one move; folder `pack` holds `RESERVATION` + `wood.jpg`; age the
  reservation file; `preview` says `("unpacked", out/pack/room.max)`; `unpack` gives `out/pack` (not `pack (2)`),
  listing `[MARKER, room.max, stone.png, wood.jpg]`.
- [ ] `test_a_recent_reservation_is_left_alone`: same crash, not aged: next unpack goes to `pack (2)`, `pack`
  untouched.
- [ ] `test_a_reserved_folder_with_other_files_is_left_alone`: aged, plus a `notes.txt`: kept, `pack (2)`.
- [ ] `test_a_crash_after_the_scene_moved_is_used_in_place`: crash after all three moves (before the marker),
  aged: next unpack is `in_place` on `out/pack/room.max`, nothing removed.
- [ ] `test_a_complete_unpack_leaves_no_reservation`: covered by existing listings; add an explicit check that
  the reservation file is gone and that a failing removal of it keeps the complete folder.
- [ ] `test_a_bad_reservation_file_is_not_stale`: aged reservation that is not JSON / not naming the scene /
  is a folder: left alone.
