# Controllers beside block-held references: fixture and slot rule Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A committed fixture, `pblock_animated`, shows where a ParamBlock2 keeps the controller of an animated
parameter when the block also holds references, and `maxdrop/reader/pblock.py` follows what it shows.

**Architecture:** `tools/fixtures/pblock_animated.ms` saves a VRayBlendMtl (base, two coats and a blend map: block
references; `blend[2]` and `texmap_blend_multiplier[1]` animated), a VRayMtl (diffuse and reflection glossiness
animated) whose bump is a VRayNormalMap (normal and bump map; both multipliers animated). The oracle gets layout
version 8: a block-level `controllers` list (`id`, `tab`, `class_id`, `slot`, `value`), the slot found by scanning
the block's references for the controller (`IParamBlock2.GetControllerByID`). The probe already disagrees with the
reader's rule: a controller takes the next reference slot in entry order, like a block-held reference, not a slot
after all of them. `pblock.py` gets one slot counter for both; a damaged entry that may hold either loses every
later slot.

**Tech Stack:** MAXScript (3ds Max 2020 + V-Ray 5.2, `3dsmaxbatch.exe`, the ViewCube / solid-background wrapper),
plain Python `unittest`, Blender 4.2 / 4.5 / 5.2 headless.

Bead: maxdrop-em3.20

## Facts measured (3ds Max 2020, probes outside the repo)

- `GetControllerByID id tab` and a scan of `pb.GetReference r` (same native pointer): VRayBlendMtl block 0 with
  base, coats 1 and 2, `texmap_blend[1]` a Checker, `blend[2]` and `texmap_blend_multiplier[1]` animated: NumRefs
  39; base 0, coats 1-2 (slots 1-9), `blend` tab 1 (Bezier Color `0x2011`, superclass `0x9005`) slot 10,
  `texmap_blend` 11-19 (the Checker at 11), `texmap_blend_multiplier` tab 0 (Bezier Float `0x2007`, superclass
  `0x9003`) slot 20. VRayNormalMap: `normal_map` 0, `normal_map_multiplier`'s controller 1, `bump_map` 2. VRayMtl
  block 1: diffuse 0, reflection_glossiness 1 although glossiness got its controller first: entry order, not
  creation order. The reader (rule "controllers after every block reference") gives the VRayNormalMap's multiplier
  the bump map (`Animated(<Noise>)`) and the VRayBlendMtl's two `Animated(None)`.
- A Bezier Float keeps its saved value in `0x7127{0x2501: f32}`, a Bezier Color in `0x7127{0x2501: 3 x f32}`
  (0..1), keys in `0x2525` / `0x2526`. Saved at frame 0 with keys at 0 and 50, `0x2501` is the frame-0 value.
- An import of the probe on Blender 5.2 passes: no converter breaks on an `Animated` material value.
