# Curves: bound _mixed's work Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `_mixed()` in `maxdrop/convert/materials.py` gives the same issue line (or None) for every curve while
asking `MaterialConverter.source_for` at most once per distinct (material index, material ID) pair of the curve's
mixed splines, instead of splines x IDs x users x MAX_PEEL steps.

**Architecture:** Only the body (and docstring) of `_mixed` changes; `_group`, `source_for` and `assign` stay as
they are. The users are reduced to their distinct material indices (the line always names `cd.users[0]` and the
first spline any user mixes, so user order never mattered). Every ID of a mixed spline gets a kind: the tuple of
its sources over those materials, interned to a small int (one `source_for` per pair). A spline mixes iff its IDs
have more than one kind; the splines are then walked in order with dict lookups only (linear in their IDs), so the
first mixing spline and the message are unchanged. The cache lives in one call: `source_for` reads `_peels`, which
grows as later curves and meshes convert, so a cache on the converter could change later lines.

**Tech Stack:** plain Python (no numpy in `_mixed`: em3.154 runs the plain suite with numpy blocked).

Bead: maxdrop-em3.147

## Optional part left out: comparing the converted IR

The bead allows comparing what the slots compare (the IR, by identity) so that two entries that draw the same are
not a mix. Left out:

- Equal sources give the same IR (material_for converts the source or a wrapper whose peel is the source).
- Different sources that draw the same are only wrappers not yet peeled around one base (a wrapper only a mixed
  spline's other ID reaches). Telling them apart needs `peel()` (it counts `stats.peeled`: the check must convert
  and count nothing, `test_curve_mixed_ids_convert_no_unused_material`) or a non-counting copy of `peel()`'s walk
  over `_sub`, which part E owns (em3.136).
- Two greyed entries are distinct IR objects (`_grey` per object), so the slots split them too: no false line there.

The remaining false positive is an extra report line for a crafted or unusual material; it stays, written in the
close note.
