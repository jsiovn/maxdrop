# Gamma-off group (maxdrop-6n0.6.18, .19, .20, .21) Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four gamma-off beads in one cycle: every kept map at a gamma-off color root or in a mask computed on the
values V-Ray holds (.18), the bump-slot reading of a VRayBitmap From 3ds Max settled (.19), the display-referred
lighting decided (.20), and a float dome's sky seen by the camera decoded (.21).

**Architecture:** convert/texmaps.py extends the em3.158 STORED rule (a STORED graph under one Decode) to Falloff,
Color Correction, Output, RGB Tint, a slot's amount, and to mixes inside a mask (the mean decoded); the builder draws
a Color Correction's saturation as 3ds Max does (HSL). convert/lights.py marks a gamma-off float dome texture, and
build/world.py splits the World by a Light Path (camera rays: the value decoded). .19 and .20 end in docs.

**Tech Stack:** Python 3.11 (plain for convert/, bpy for build/), 3ds Max 2020 + V-Ray 5.2 and Corona 12 probes
(3dsmaxbatch, local), Blender 4.2 / 4.5 / 5.2 headless.

## Probes (done before the plan; local, outside the repo)

One 3dsmaxbatch session (`C:\maxdrop_fixtures\probe\6n0_6_group\run_all.ms`): `6n0_6_18\probe.ms` (V-Ray, 36
VRayLightMtl / VRayMtl self-illumination planes, an orthographic camera, Falloff planes tilted 60 degrees),
`6n0_6_19\probe.ms` (V-Ray, VRayBumpNormals of a ramp height in ten slots), `6n0_6_21\probe.ms` (V-Ray dome, white
and grey mirrors, multiplier 2), `6n0_6_18\corona.ms` (Corona 12, 10 planes). Findings:

- .18: with the gamma on and off V-Ray gives the same internal value on every swatch plane (Falloff 0.333 / 0.510,
  Color Correction brightness / contrast / gamma / gain / saturation / hue, Output level and offset, RGB Tint, a
  self-illumination amount of 50 % 0.510, a Mix, Composite, Falloff or Color Correction inside a mask): every one is
  computed on the stored values; a Bitmap inside is read as stored (gamma off) or decoded (on). Corona 12 alike for
  Mix, Composite, Falloff, Color Correction, Output, Tint, CoronaMix, a Mix in a mask. Before: 26 of 36 V-Ray planes
  and 5 of 10 Corona planes over 0.02 with the gamma off (worst 0.327). Also with the gamma on: Color Correction's
  saturation is HSL (towards (max + min) / 2; -50 % over (200, 100, 50) stored: 0.637 / 0.441 / 0.343, the builder's
  HSV 0.784 / 0.588 / 0.490), and a custom rewiring in a mask picks the channel (red to all: 0.784, MaxDrop the
  mean 0.457).
- .19: a VRayBitmap From 3ds Max height reads as stored with the gamma off in every slot tried (VRayMtl bump
  directly, under an Output, a Mix, Normal Bump's and VRayNormalMap's bump input) and decoded with the gamma on, as a
  Bitmap automatic. em3.159's "decoded directly in the bump slot" does not reproduce: its own probe2.ms run again in a
  fresh session gives stored (1.73 / 1.73 degrees; decoded is about 2.87 / 0.85). A Standard material's bump slot is
  not in VRayBumpNormals (flat in both modes): not measured. MaxDrop's rule already reads it as stored: no code change.
- .21: the mirrors are sky times reflectance (white 0.5 / 4.0, grey 0.251 / 2.008, uni050 x 2: sky 1.0): a sharp
  reflection of a uniform sky follows the camera reading (white 0.214 target: camera 0.214, light 0.5), but a rough
  reflection of a sun would take the camera reading's dec(2000) like the material rule's floor (em3.166: 1664 times):
  glossy rays keep the light's reading. V-Ray's sky is multiplier x texel: the camera reading decodes the product.

## Decision for .20 (gate)

Stay as it is, cost documented. The candidate (V-Ray's internal values everywhere, shown unencoded through Blender's
Raw view) is measured by what exists: V-Ray's internal value is the same with the gamma on and off on every probe
row (em3.123, em3.158, em3.165, em3.166 and the .18 probe), and the gamma-on imports match it within 0.007 to 0.0092;
the Raw view shows a value as its byte (checked on 4.2, 4.5, 5.2 in the matrix). It is not shipped: view settings
belong to the whole Blender scene (an import into a file with other content, or a second gamma-on import, cannot both
be right), and as an option it would need its own image rules (a Bitmap override read as stored, CoronaNormal's add
gamma) across the gamma-off branches. Docs: FORMAT.md (the em3.166 bullet), SUPPORT.md.
