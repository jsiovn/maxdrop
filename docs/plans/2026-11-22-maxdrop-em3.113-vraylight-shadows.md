# VRayLight shadow switch Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a VRayLight whose own Cast shadows switch is off in 3ds Max casts no shadows in Blender (bead
maxdrop-em3.113; em3.72 did the standard, photometric and VRayIES lights).

**Architecture:** convert/lights.py reads parameter 32 of the VRayLight's ParamBlock2 into its values
(`P_SHADOW`), `describe` sets `LightDescription.shadow`; build/lights.py already sets `Light.use_shadow` from it. A
dome with shadows off is a report line (a World has no shadow switch). No new module, no compat entry.

**Tech Stack:** Python 3.11 syntax, plain unittest, Blender 4.2 / 4.5 / 5.2 headless, 3ds Max 2020 + V-Ray 5.2
(3dsmaxbatch for the probe and oracle, an own interactive 3ds Max through 3dsmax-mcp for the fixture save).

---

## Probe result (3dsmaxbatch, 3ds Max 2020 + V-Ray 5.2, scratch scene outside the repo)

The VRayLight's ParamBlock2 (reference 0, block id 0) read through the SDK's .NET wrapper (`GetParamDef`), before
and after `l.baseObject.castShadows = false`: id **32** `castShadows`, type 4 (BOOL), default **1**; it is the only
parameter that changed. The node's Cast Shadows render flag (`l.castShadows`) stayed true: the trap of em3.72.
A VRayLight made by MAXScript starts with shadows on (unlike the standard and photometric lights).

## Rules

- `P_SHADOW = 32`, `DEFAULTS[P_SHADOW] = 1`, `_NAMES[P_SHADOW] = "castShadows"`: a value not stored, animated or
  not finite reads as on (as the others: a file that does not store it keeps its shadows).
- `describe`: `shadow=bool(values[P_SHADOW])`. No issue: Blender does the same.
- `describe_dome`: shadows off -> issue `DOME_SHADOW` ("shadows off is not imported: the World always casts
  them"); the World is built as before.
