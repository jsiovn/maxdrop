the repo) and `tools/maxdiff.py` on one-change saves. Only registration lines in the test tables; no `maxdrop/` code.

## Blocker

With the fixture in `tests/fixtures/` and the table lines added, `python -I -m unittest discover tests` fails only in
`unit.test_pblock.OwnerSlotsOnFixtures.test_blanked_blocks_resolve_the_same` (FixtureCheckerNested: pids 3 and 4;
FixtureGradientLinear and FixtureGradientRadial: pid 20, the Output every Gradient has): the test blanks every
block's owner-held references as a 3ds Max 2012 (format 14000) file stores them and needs the owner slots of the
class in `maxdrop/reader/owner_slots.py`, which has no Checker and no Gradient. The two lines that make it pass
(checked, then reverted), the fixture's own `0x0013` tables:

```python
    (_TEX, ClassId(0x200, 0)): {0: {3: 2, 4: 3}},  # Checker: map1, map2
    (_TEX, ClassId(0x270, 0)): {0: {3: 2, 4: 3, 5: 4, 20: 5}},  # Gradient: map1-3, output
```

That is `maxdrop/` code, which this bead excludes, and it changes how the reader resolves a Checker of maps and every
Gradient in a 2012-format file. The bead asks for both (a Checker whose sides are Checkers; Gradients), so no
narrower fixture avoids it. The same owner choice as maxdrop-o53.2.3 (Blend): allow those reader lines in this bead,
or land the fixture with the code-lane bead that adds the classes.
