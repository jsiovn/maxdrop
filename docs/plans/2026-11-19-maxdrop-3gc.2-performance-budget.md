# Performance budget for large scenes Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A time and memory budget that a change cannot silently break: two benchmark tests (plain Python and
Blender) that fail on a 3x slowdown, a few local fixes of the top offenders the profile names, and the corpus budget
measured and recorded in `docs/BASELINE.md`.

**Architecture:** One synthetic Editable Poly generator (`tests/synthetic_poly.py`, numpy, no commercial data) feeds
both benchmarks. Times are never compared with a fixed number of seconds: each benchmark divides the best of N runs
of the workload by the best of N runs of a reference workload of the same character timed in the same process, and
the limit is about twice the ratio measured here. Memory is the `tracemalloc` peak as a multiple of the input size,
which is deterministic. The plain benchmark is found by `unittest discover tests`; the Blender one is
`tests/blender/bench.py`, runnable alone and called by `tests/blender/run.py`, so CI's existing fixture step runs
it without a workflow change (the workflow is outside this bead's files).

**Tech Stack:** Python 3.11 syntax, numpy (1.24.3 .. 2.3.4), `unittest`, `tracemalloc`, Blender 4.2 / 4.5 / 5.2
headless.

## Fixes (local, covered by tests)

- **F1** `convert.scene.sharp_edges`: the key array is already sorted (`argsort(kind="stable")`); `numpy.unique` sorts
  it again. Find the runs of equal keys with one comparison of neighbours instead. Same output.
- **F2** `convert.scene.valid_faces`: `numpy.unique(rows, axis=0)` sorts rows as opaque records. Use a stable
  `numpy.lexsort` over the sorted rows' columns and compare neighbours: the first row of each run is the earliest
  face (lexsort is stable), the rest are doubled. Same output.
- **F3** `build.objects._sharp_edge_flags`: no sharp pair -> all False without reading the edges; otherwise
  `numpy.searchsorted` into the sorted, unique pair keys instead of `numpy.isin`. Same output.
- **F4** `reader.geometry._poly_faces`: only if F1-F3 leave it the top offender and a slimmer loop gives a clear gain
  on the benchmark; every malformed-input guard and message stays (tests/unit/test_geometry.py).

Acceptance of each fix: the existing unit tests and `FIXTURES PASSED` unchanged on all three Blenders; on the corpus
the same vertex, polygon, object, material and image counts as before, peak memory not higher.

## File structure

- Create `tests/synthetic_poly.py`: `poly_object(faces, seed=0)` -> bytes of an Editable Poly object chunk (a
  0x08FE geometry container: 0x0100 vertices, 0x011A faces of mixed degree (quads and triangles, mask flags +
  material + smoothing, diagonals on quads, a few doubled and degenerate faces), one map channel 0x0124 / 0x0128 /
  0x012B), built with numpy, deterministic; `reference_loop(data)` and `reference_numpy(n)` the reference workloads.
  Not named `test_*`: unittest does not collect it.
- Create `tests/unit/test_perf.py`: plain benchmark (skips without numpy): reader time ratio, describe time ratio,
  tracemalloc peak of read + describe as a multiple of the chunk size.
- Create `tests/blender/bench.py`: Blender benchmark: 1 M faces through reader + `mesh_description` +
  `build.objects.make_mesh`, time ratio against a bare `foreach_set` mesh of the same arrays; prints `BENCH PASSED` /
  `BENCH FAILED` when run alone; `run(check)` when called from run.py.
- Modify `tests/blender/run.py`: call `bench.run(check)` in `main()` (not with file arguments).
- Modify `maxdrop/convert/scene.py` (F1, F2), `maxdrop/build/objects.py` (F3), maybe `maxdrop/reader/geometry.py`
  (F4).
- Modify `docs/BASELINE.md`: a "Performance budget" section: budget, measurements, where time and memory go, the
  benchmarks and how to run them.

## Chunk 1: benchmarks

### Task 1: synthetic generator

- [ ] Write `tests/synthetic_poly.py` (SPDX GPL-3.0-or-later header). Grid of `w x h` vertices; faces = quads, every
  third quad split into two triangles; smoothing groups in bands so that some edges are sharp; material IDs 0..3;
  every 1000th face doubled (same vertex set) so `valid_faces` drops some. Records are laid out with numpy: compute
  each record's size, `offsets = cumsum`, then write each field through `buf[offsets[:, None] + arange(k)] =
  values.astype("<u4").view(uint8).reshape(-1, 4)`.
- [ ] A unit test in `test_perf.py` reads a small generated object (`faces=200`) with `geometry.read_editable_poly`
  and checks the face count, the degrees, the doubled faces dropped by `mesh_description` and one map channel.

### Task 2: plain benchmark `tests/unit/test_perf.py`

- [ ] Load the reader through the stub package `maxdrop_convert_test` (as the other unit tests).
- [ ] `best(fn, n)`: the minimum of n `time.perf_counter()` runs.
- [ ] Reader ratio: `best(read_editable_poly(chunks.index(buf)[0]))` / `best(reference_loop(buf))`, where the
  reference walks a buffer of the same record count with `struct.unpack_from` and `array.append` (the same kind of
  Python work as `_poly_faces`).
- [ ] Describe ratio: `best(mesh_description(...))` / `best(reference_numpy(loops))` (a stable argsort and a sort of
  int64 arrays of the loop count: the same kind of numpy work).
- [ ] Memory: `tracemalloc` peak of read + describe divided by `len(buf)`, run once, separately from timing.
- [ ] Measure the ratios on the local Python and on the Pythons bundled with Blender 4.2 (3.11, numpy 1.24.3), 4.5
  (3.11, numpy 1.26.4) and 5.2 (3.13, numpy 2.3.4); set each limit at about twice the largest; the memory limit at
  about 1.5x the measured multiple. If the ratios differ by more than 1.5x between those, change the reference.
- [ ] On failure the message prints the measured ratio, the limit and both times.

### Task 3: Blender benchmark `tests/blender/bench.py`

- [ ] Generate 1 M faces (`poly_object(1_000_000)`), read and describe once (outside the timing), then time
  `make_mesh(md)` (best of 3, each mesh removed after) against a reference that makes a mesh of the same arrays with
  `vertices.add/loops.add/polygons.add`, `foreach_set` of `co`, `vertex_index`, `loop_start` and
  `update(calc_edges=True)` (best of 3). Also time read + describe against the plain references. Limits about twice
  the measured ratio on 5.2, 4.2 and 4.5.
- [ ] `run(check)` for run.py; standalone prints `BENCH PASSED` (exit 0) / `BENCH FAILED` (exit 1).
- [ ] Hook into `tests/blender/run.py` `main()` beside the other checks (only without file arguments).

## Deviations found while executing

- The numpy reference is `numpy_reference(values)`: int64 arithmetic, a gather and a comparison of neighbours into
  preallocated arrays, no sort and no allocation (sorts differ 2x between numpy 1.24 and 1.26, large allocations
  between Blender builds); workload and reference runs alternate (`timed()` in `tests/synthetic_poly.py`).
- The memory limit is 5.3 against a measured 5.07 (not 1.5x): tracemalloc's peak is exact, and the tighter limit
  fails one more int64 array per loop.
- F4 declined: the prototype gave 25 to 30 % of `_poly_faces` (0.3 s and 0.5 s on the corpus).
- `valid_faces` also refuses faces of fewer than three loops (unreachable from the readers; `lexsort` cannot take
  zero columns).
