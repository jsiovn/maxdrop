# Gamma-off color mixes on stored values Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** in a scene saved with the gamma off, draw a Mix or Composite in a color graph as V-Ray 5.2 renders it: the
mix computed on the stored (display) values and the result decoded once (bead maxdrop-em3.158).

**Architecture:** the probe below shows V-Ray's internal value of every mixing plane is the same with the gamma on
and off; with it off the scene is display-referred, so Blender needs `srgb_to_linear` of it. The converter already
matches V-Ray to 0.0000 on stored values (its gamma-on numbers). So in a gamma-off scene a Mix or Composite at a
COLOR kind is converted in a new kind STORED (a color as V-Ray computes it there: swatches as stored, images by their
own decode, a Bitmap as stored; masks DATA) and wrapped in one new IR node `Decode` (the builder: a Gamma node of
2.2; a Constant folded exactly with `srgb_to_linear`; a lone Image converted again as COLOR). Kept as today: a Mix
between its colors black and white without side maps or a curve (maxdrop-em3.36, exact: the mask decoded, and now
the mix amount too). RGB Multiply at a color root stays as it is (0.005 off: a product commutes with a power law).

**Tech Stack:** 3ds Max 2020 + V-Ray 5.2 (`3dsmaxbatch`, scratch MAXScript), plain Python `unittest`, Blender 4.2 /
4.5 / 5.2 headless.

Why one decode and not Gamma nodes around each mix (the bead's first idea): sides already decoded by the sRGB curve,
re-encoded by 1 / 2.2, are up to 0.023 off (a 0.04 grey against white), 0.020 on Addition; a single 2.2 decode of
stored values is within 0.009 of the sRGB curve on 0..1.
