# Shell sides and evaluated shading against 3ds Max Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Shell whose two surfaces lie on one side of the original, or whose amounts turn it inside out, arrives
as a Solidify that matches 3ds Max (place and facing); the oracle says how an evaluated mesh is shaded, and
`tests/blender/run.py` compares Blender's evaluated shading of every converted node with it.

**Architecture:** `convert/modifiers.py` stops refusing a one-sided Shell (Solidify's `offset` has no hard range)
and sets `use_flip_normals` when inner + outer < 0. `tools/oracle/dump_scene.ms` layout 10 adds
`eval_mesh.smoothing` (`flat`, `regions`, `hard_edges` of the evaluated TriMesh's smoothing groups). A new
fixture `stack_shell` holds open boxes with one-sided, inward, crossed and default Shells. The rim's shading
(needs `convert/scene.py` and `build/modifiers.py`, outside this bead's Files) becomes a debt bead with the
measured design; this bead documents it and lists the nodes as a known difference.

**Tech Stack:** MAXScript (3ds Max 2020: `3dsmaxbatch.exe` for probes and oracles, an own interactive instance
through the 3dsmax-mcp bridge for the fixture save), plain Python `unittest`, Blender 4.2.23 / 4.5.16 / 5.2.

Bead: maxdrop-em3.53

## Facts measured (probes outside the repo, 3ds Max 2020 and Blender 5.2 / 4.2)

- Shell parameters (MAXScript names): `autosmooth` default true (id 14), `autoSmoothAngle` 45 (id 15),
  `overrideSmoothingGroup` false (id 4), `smoothGroup` 0 (id 5). A negative inner or outer amount is kept.
- Surfaces at -inner and +outer along the vertex normals in every case; Blender's Solidify with thickness hi - lo
  and offset (hi + lo) / (hi - lo) (lo, hi = min / max of -inner, outer) gives the same box and the same signed
  volume for offsets past -1..1 (inner -1 outer 2: offset 3; inner 3 outer -1: offset -2), closed and open boxes.
- Inner + outer < 0 (e.g. -2 / 1, 1 / -2, -1 / -2): 3ds Max's result is inside out (signed volume negative,
  -1636.42 for -2 / 1 closed); Blender matches with `use_flip_normals` on, not without. -1 / -2 is accepted
  today without the flip: wrong facing today.
- Smoothing metric `[flat, regions, hard]` (flat = triangles of group 0; regions = connected components of the
  smoothed triangles through manifold edges whose faces share a group bit; hard = manifold edges between two
  smoothed triangles that share none). Blender equivalent on the evaluated mesh: flat polygons' triangles,
  components of smooth polygons through manifold edges not marked sharp, manifold sharp edges between two smooth
  polygons. Open box base: Max (0, 5, 8) = Blender (0, 5, 8).
- Rim: 3ds Max gives the rim its own groups, hard against both surfaces: open box with Shell 0 / 1, auto smooth on
  or off, (0, 11, 24); Blender's Solidify smooths the rim into both surfaces: (0, 3, 16). With the open (boundary)
  edges marked sharp before the Solidify, Blender gives (0, 11, 24) on 5.2 and 4.2. Auto smooth also splits the
  rim at corners sharper than its angle (plane: Max (0, 6, 12), auto off (0, 3, 8); Blender with sharp boundary
  (0, 3, 8)). Override group with auto smooth off: the rim takes that group, and merges into a surface that has it
  (open box, group 4 of a side: (0, 9, 22)); with auto smooth on the override has no effect (rim group as without
  it). TurboSmooth (Smooth Result) then Shell: Max (0, 3, 16) (the rim avoids the smoother's group 1);
  Shell then TurboSmooth: (0, 1, 0).
- `3dsmaxbatch.exe` exits 127 even on success: read success from the file the script writes.
