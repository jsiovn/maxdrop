# A constant below a color wrapper keeps its color Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a constant below a wrapper that works on color (RGB Tint, an Output part, Color Correction) in a data,
bump or normal input keeps its three channels, so the wrapper acts on the color and the mean is taken after it, as
V-Ray does (bead maxdrop-em3.128); a constant color in a normal map's normal input is drawn, not flat.

**Architecture:** `maxdrop/convert/texmaps.py` gets two kinds for the input of a color wrapper inside a float graph:
DATA_RGB and BUMP_RGB (`rgb_kind()` / `base_kind()`). In them, and in NORMAL, a swatch is a Constant of its three
channels as stored (clamped); images and masks below behave as in the base kind (`_image` and `_normal` take
`base_kind`, `mask_kind` already gives DATA). The Tint's own rows follow the same rule (stored in DATA, BUMP, NORMAL;
decoded in COLOR and MASK). The builder already draws Tint, Adjust and ColorCorrect in COLOR and averages a color
socket on a float input; its `normal_map` now draws a constant color through an RGB node.

**Tech Stack:** Python 3.11, plain `unittest`, Blender 4.2.23 / 4.5.16 / 5.2 headless.

---

## Evidence (no new measurement)

- maxdrop-em3.76 (3ds Max 2020, V-Ray 5.2, gamma off): an RGB Tint with rows (128,0,0 / 0,64,0 / 0,0,32) and no
  map renders 0.293 on opacity: the mean of the tinted white with the rows **as stored** (0.502, 0.251, 0.125).
  MaxDrop today: 0.094 (rows decoded by the gamma-off swatch rule, probed in this session). In a VRayNormalMap's
  normal slot the white of an empty Output / RGB Tint tilts the normal as a white map does; VRayColor2Bump's
  (0.5, 0.5, 1) is flat.
- maxdrop-em3.122: a data input takes a swatch as stored, gamma on and off. With the gamma on stored = linear, so
  only gamma-off tests tell the rules apart: every new test runs under GAMMA_OFF too.
- maxdrop-em3.124: a Multiply in a float graph is the product of the sides' means (V-Ray's mono value): unchanged,
  a Multiply at a data root still gets float constants. Below a Tint the Tint asks for color, so its sub-graph is in
  DATA_RGB and a Multiply there is per channel.

## Decisions

- Kinds: `DATA_RGB = "data rgb"`, `BUMP_RGB = "bump rgb"`. `rgb_kind(kind)`: DATA -> DATA_RGB, BUMP -> BUMP_RGB,
  any other kind itself. `base_kind(kind)`: the inverse. They are cache-key values of `_nodes` / `_firsts`, so a map
  shared by a bare slot and a Tint gets two nodes.
- `_swatch(rgb, kind)`: COLOR -> `swatches.color`; MASK -> `swatches.channel(mean)` (unchanged); DATA, BUMP -> the
  mean as stored (unchanged); DATA_RGB, BUMP_RGB, NORMAL -> the clamped channels as stored (tuple). A helper
  `_linear(rgb, kind)` gives CoronaColor's HDR and gamma-on kelvin colors the same shape (tuple in COLOR and the
  stored-RGB kinds, the mean otherwise).
- Output: its part read first; no change (`_output` None) -> its map in the Output's own kind (a bare swatch keeps
  the data rule, em3.36 / em3.122), else in `rgb_kind(kind)`. RGB Tint: rows read first, in COLOR for COLOR / MASK,
  else in `rgb_kind(kind)` (stored); identity -> its map in its own kind, else `rgb_kind(kind)`. Color Correction:
  its map and its own color always in `rgb_kind(kind)` (always wrapped in a ColorCorrect, never a bare swatch).
- `_wrapped` no longer refuses NORMAL: an empty Output / RGB Tint there is white (stored), drawn as a tilt; an empty
  VRayColor2Bump is (0.5, 0.5, 1), flat. Both as measured.
- Builder `normal_map`: MISSING -> None (flat, as today); a constant color -> an RGB node into the Normal Map node
  (`self.socket`), through the flips like an image.
- MASK stays as it is: its rule is decode(mean), which no per-channel constant can express; a Tint as a mask over a
  constant keeps a grey input. Filed as a P4 debt bead in this part.
- Falloff's own Output stays in the Falloff's kind: an Output is a uniform affine map, the mean does not move.
