# Hostile input: limits, guards and fuzz tests Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A malformed or malicious `.max` file or scene pack ends in a clear error message (one exception family,
`MaxFileError`), never in a hang, a memory blow-up or a traceback; a deterministic fuzz harness proves it in CI
and in a large scratch campaign.

**Architecture:** `maxdrop/reader/errors.py` holds `MaxFileError(ValueError)`; every reader error (CfbError,
ChunkError and its subclasses, MetadataError) and the intake's PackError derive from it, so every existing
`except ValueError` keeps working. One harness module, `tests/unit/fuzz.py`, makes case k of a fixture a pure
function of (seed, fixture name, k) and runs it through the path the operator runs (preflight, then
`_read_scene` without Blender); unit tests run a bounded slice, its `__main__` runs the multi-process campaign.
The zip intake gets the same harness with a per-case sandbox.

**Tech Stack:** Python 3.11 syntax, stdlib (`random`, `multiprocessing`, `faulthandler`, `zipfile`), numpy.

## Task 4: `.max` harness and CI slice

- [ ] `tests/unit/fuzz.py`: loads the reader under its own stub package. `Seed(path)`: raw bytes, the file runs
      of header / FAT / directory sectors and of the streams Scene, ClassDirectory3, DllDirectory,
      FileAssetMetaData3, Config, SummaryInformation, DocumentSummaryInformation; the file offsets of every chunk
      header of Scene / ClassDirectory3 / DllDirectory and of the leading u32 of each leaf; the directory entry
      fields. `case(seed, k, base_seed)` -> (bytes, spec) with `random.Random("%d/%s/%d")`; mutation kinds:
      `flip` (bits in a weighted region), `bytes`, `cut` (file truncation), `chunk_size` (extreme values: 0, 1, 5,
      6, 7, 13, 14, 0x7FFFFFFF, 0x80000000, 0x80000006, 0xFFFFFFFF, size +-1), `container` (bit 31), `count`
      (leading u32 of a leaf to an extreme), `dir` (a directory entry's start / size / left / right / child),
      `header` (nfat, first directory, mini FAT, DIFAT fields), `swap` (two sectors). Stream offsets map to file
      offsets byte by byte through `Stream.runs`.
- [ ] `run(data, scratch_dir)` mirrors the operator: `_preflight` (metadata, MetadataError swallowed, Scene,
      units) then `_read_scene` (Scene, units, AssetTable, describe with assets and saved views, then the material
      stage `MaterialGraph` / `TextureIndex` on an empty folder / `TexmapConverter` / `MaterialConverter` /
      `assign`, and `colors.of_scene(...).note`). Outcomes: `ok`, `refused` (MaxFileError), `materials` (an
      exception of the material stage, which ops catches: allowed, counted), `escaped` (anything else: a failure).
- [ ] `tests/unit/test_fuzz.py`: for each fixture CASES (env `MAXDROP_FUZZ_CASES`, default sized so the slice
      takes about 10 s locally) cases; per case `faulthandler.dump_traceback_later(60, exit=True)` as the hang
      watchdog and an assert of under 5 s; no `escaped`; process peak memory (Windows PeakWorkingSetSize,
      POSIX ru_maxrss) under 1 GB after the slice. A failure prints the replayable case id.
- [ ] `test_malformed.py`: `assertOnlyValueError` -> MaxFileError; cut / garble counts trimmed so the module stays
      about 20 s (the structural record / reference tests stay).
- [ ] Commit `Add a deterministic fuzz harness for .max files`.

## Task 6: Zip harness, name policy, texture paths

- [ ] Zip harness in `tests/unit/fuzz.py`: seed pack (scene .max, maps in folders, a .ies, a readme, a folder entry,
      stored and deflated); mutations of the central directory (names, sizes, flags, methods, extra lengths,
      offsets), local headers, the end record (counts, offsets), truncation, bit flips. Per case a sandbox
      `<case>/pack.zip` + `<case>/out`; `list_pack`, then `unpack` of the first scene. RAR / 7z backends popped:
      no program is started. Outcomes `ok` / `refused` (PackError); afterwards nothing outside `<case>/out` except
      the pack, no `.maxdrop-staging-*` left, the sandbox's parent unchanged.
- [ ] `tests/test_intake_fuzz.py`: the CI slice (about 150 cases) and the name-policy property test: random byte
      strings decoded several ways plus risky tokens; `refused_reason(name) is None` implies no separator, colon or
      control character, not reserved, no trailing dot or space; and for a sample, the file created in a fresh
      folder is the only entry there, with the same name_key.
- [ ] `test_textures.py`: random stored paths from risky tokens (UNC, device, `..`, drive-relative, streams,
      reserved names, control characters, mixed separators): an accepted path has the shape refused_reason
      promises; `TextureIndex.find` never passes a refused path to `is_local_drive` or `os.lstat`, and never lists
      a folder outside the scene tree.
- [ ] Commit `Fuzz the zip intake, the name policy and stored texture paths`.
