# One password message for scene packs Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected pack gives one message, naming the archive, whichever backend found it; entry names
are shown with `/` on every backend; no message says "drop the .max" any more (wrong after File > Import).

**Architecture:** `maxdrop/intake/archive.py` owns the text: `password_message(path)` and the tail
`BY_HAND_TAIL` ("Extract the archive by hand and import the .max from that folder."). The zip backend
(encrypted flag, `RuntimeError` from `zipfile`) and `_refuse_unreadable` (any backend's `encrypted` flag) call it
with the archive path; `external.py` calls `_archive.password_message` for the header check and for program output
that mentions a password. `_read_entries` turns `\` into `/` in every entry name, once, for every backend (the
names are already split on both); a marker written by an earlier version with `\` still matches.

**Tech Stack:** Python 3.11 stdlib, `unittest`, Blender 4.2 / 4.5 / 5.2 headless.

---

## Message

```
<archive base name> is password-protected: MaxDrop does not ask for passwords. Extract the archive by hand and import the .max from that folder.
```

`_BY_YOURSELF` in `external.py` ("Extract the archive yourself, then drop the .max.") becomes the same tail
(literal copy: `external.py` is imported while `archive.py` is still loading), and the two inline
"extract the archive yourself, then drop the .max" texts of `_none_message` say "extract the archive by hand and
import the .max from that folder".
