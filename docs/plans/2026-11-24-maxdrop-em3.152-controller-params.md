# Material and map parameters held by a controller: frame-0 value (maxdrop-em3.152) Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A material or map parameter that a controller holds (`reader.pblock.Animated`) converts to its
controller's value at frame 0 instead of the class's default, wherever the material and map rules read a parameter.

**Architecture:** One choke point. `convert/params.py` gets a resolver (`frame_zero`) and two thin proxies:
`FrameZeroGraph` wraps a MaterialGraph so `get()` hands out `FrameZero` materials, whose `param()` resolves an
`Animated` through a new reader helper `controllers.parameter_value(scene, i)` (built on `_Eval`, like the
module-level `matrix()`). `MaterialConverter` and `TexmapConverter` wrap their graph once in `__init__`; `_PartParams`
(a Standard material's shader block) resolves through the same function. `num`, `flag`, `_num_tab`, `_flag_tab`, the
color readers (`rgb`, `mono_swatch`, `_constant`, `_vec`) and the Color Correction rewiring all read through
`m.param` and so need no change of their own; no rule body (part F's `corona_legacy_mtl`, `_group`, `_mixed`
included) is edited. The reader (`MtlBase.param`, `pblock`) keeps returning `Animated`: the raw-parameter parity
test and `test_animated_by_id` pin that.

**Tech Stack:** plain Python 3.11 (reader/ and convert/ never import bpy); unittest; Blender 4.2 / 4.5 / 5.2 headless.

## Findings (code is right where it and the bead disagree)

- The bead says `reader/controllers.py` "already evaluates float and color controllers". It evaluates float ones
  (`_Eval.scalar`: the keyframed floats and Float List); no Point3 / color controller is read. pblock_animated's
  animated colors are **Bezier Color**, `(SC_CTRL_POINT3 0x9005, ClassID (0x2011, 0))`: saved value `0x2501` as
  3 x f32 (not `0x2503`), interval `0x2500`, keys `0x2526` at 80 bytes per key (the Bezier Position layout; 160 bytes
  for the fixture's two keys). So `classids.py` gains `BEZIER_COLOR` (the fixture already holds the class:
  `test_classdir.test_every_known_class_is_in_a_fixture` passes) and `_KEYFRAMED` an entry. `classids.py` is outside
  the bead's Files list but inside `maxdrop/reader/`, which is part E's alone; named in the close note.
- `_position`, `_rotation`, `_scale`, `_scalar` dispatch on the superclass first: a `SC_CTRL_POINT3` entry in
  `_KEYFRAMED` changes no transform.
- Bezier Color stays out of `_BEZIER`: between two keys `_between` returns None and the value is linear with
  `KEYS_INTERPOLATED` (the oracle pins frame 0 only; "not measured" in the code and docs/FORMAT.md).
- An integer parameter (types 1 int, 4 bool, 12 time, 13 radio, 19 index) under a float controller: 3ds Max's
  conversion is not measured (no committed fixture animates one). Accept a whole-number value as that int; any other
  value leaves the parameter unresolved (the rule's default; the Color Correction rewiring keeps its issue line).
- A value whose shape does not fit the parameter type (a float for a color, a color for a float, a point4 or
  float-color param) stays unresolved. Percent and angle parameters take the controller's value as stored, as the
  stored values are (not measured either).
- Unresolved = the `Animated` is returned as it was: every rule behaves as before (its default; the camera / light /
  modifier readers are not touched: out of scope). No new report line for an unresolved controller (not in Verify):
  a P4 debt bead in part E if wanted.
- Block-level reads that bypass `param()` (`block.value(...)` in `_wrapped`, `_multi`, the Corona layer and select
  lists, Composite's map list) read references, IDs and switches only: left as they are.
- The graph is wrapped only when it has a `scene`: `test_convert_materials`'s `FakeGraph` has none, so its
  "animated takes the default" case still holds on a stand-in; `test_texmaps`'s `FakeScene` stand-ins hold no
  `Animated`, so the scene is never asked.

```python
# classids.py
BEZIER_COLOR = ClassId(0x00002011, 0)
    (SC_CTRL_POINT3, BEZIER_COLOR): "Bezier Color",

# controllers.py
    (classids.SC_CTRL_POINT3, classids.BEZIER_COLOR): (_FLOAT_VALUE, 3, 0x2526, 80),

def parameter_value(scene, i):
    """(the value of controller i at frame 0, issues) for a parameter of a material or map (reader.pblock.Animated):
    a float from a float controller (_Eval.scalar), a tuple of 3 floats from a Bezier Color; None where it cannot be
    evaluated (another class, no saved value or keys, a damaged controller, a non-finite value), with an Issue (node
    None) as matrix() gives."""
    issues = []
    ev = _Eval(scene, None, issues)
    if not 0 <= i < len(scene):
        issues.append(Issue(None, None, None, None, "%s: object %d past the scene" % (DAMAGED, i)))
        return None, issues
    try:
        sc, cid = ev.kind(i)
        if sc == classids.SC_CTRL_FLOAT:
            value = ev.scalar(i, None)
        elif (sc, cid) in _KEYFRAMED and sc == classids.SC_CTRL_POINT3:
            with ev.at(i):
                v = ev._keyframe(i)
            value = None if v is None else tuple(float(c) for c in v)
        else:
            ev.issue(i, UNKNOWN_CLASS)
            return None, issues
    except (MaxFileError, OverflowError) as exc:
        del issues[:]
        ev.issue(ev.failed if ev.failed is not None else i, "%s: %s" % (DAMAGED, exc))
        return None, issues
    if value is None:
        return None, issues
    if not all(math.isfinite(c) for c in (value if isinstance(value, tuple) else (value,))):
        ev.issue(i, NON_FINITE)
        return None, issues
    return value, issues
```
