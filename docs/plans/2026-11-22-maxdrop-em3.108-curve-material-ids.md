# Curves: a material index per spline Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shape built as a curve gives each spline the material slot of its own segments' material ID (bead
maxdrop-em3.108): a Multi/Sub-Object on a Line whose splines are set to IDs 1 and 2 shows both sub-materials, not
ID 1's on every spline.

**Architecture:** The reader already has each segment's ID (`reader.shapes.Knot.material`, zero-based, since
maxdrop-em3.51). `convert/scene.py` puts the IDs of a spline's segments (not knots: the last knot of an open spline
starts none) on its `SplineDescription` (`material` = the first segment's, `material_ids` = the distinct ones in
segment order). `convert/materials.assign` groups a curve's distinct spline IDs exactly as a mesh's face IDs
(`material_for` per user, grouped by identity) and gives `MeshSlots.indices` one entry per spline; a spline that
mixes IDs whose users get different materials is an issue (`desc.issues`) on the curve's first user.
`build/curves.set_material_indices(curve, indices)` sets `spline.material_index` from the plan, called by
`build/objects._slots` after the curve's slots exist (Blender clamps a spline's index to the curve's materials:
found on the first Blender run, so a curve without slots keeps every spline at 0).

**Tech Stack:** Python + numpy (convert/, no bpy), bpy (build/), MAXScript in 3ds Max 2020 (oracle, fixture).

Bead: maxdrop-em3.108

---

## Facts

- Knot record 0x290A: trailing u32's high 16 bits = zero-based ID of the segment starting at that knot
  (maxdrop-em3.51 probe). The reader's parametric makers give every segment ID 0 (3ds Max shows 1): not yet
  checked against 3ds Max; the oracle has no material key per knot so far (`KNOT_KEYS` in tests/test_oracle.py).
- Blender: one `material_index` per spline (`bpy.types.Spline.material_index`), clamped by Blender to the curve's
  material count.

## Design decisions

- Oracle v12: per knot `material` = `getMaterialID t s k` (1-based, as 3ds Max shows it), `null` where `segment`
  is `null`. Every oracle regenerated (`dumpFolder`): only the version line and, in shape nodes, the new key may
  change (diff checked).
- Mixed IDs: an issue only when it changes what renders, i.e. some user gets a different material (by identity)
  for another ID of that spline than for its first: `shape: spline N mixes material IDs a, b: drawn with ID a's
  material (its first segment's)` (1-based IDs, N 1-based). Named once per curve key, on its first user. A mixed
  spline under a plain material gets none.
- A curve none of whose users gets a material stays out of `slots.curves` (unchanged); a plain material still
  gives one slot, every spline on it.
- No change to convert/extrude.py (Use Shape IDs is maxdrop-em3.51's).
