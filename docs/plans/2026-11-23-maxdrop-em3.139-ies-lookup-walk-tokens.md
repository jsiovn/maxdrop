# IES lookup: truncated search, shared walk, lazy tokens Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An import walks the texture folders once for the IES, dome and material lookups, says when that walk
stopped short (also without materials), and reads an IES file's numbers one token at a time.

**Architecture:** `TextureIndex.share()` returns a lookup over the same walk (the `_tiers` dict and the
`report.truncated` list are the same objects) with its own cache and its own found/missing counts. `ops._read_file`
makes one index and hands a share to the scene description (IES), the dome texture and the materials; `_Read`
carries the walk's truncated list, and `_import_scene` puts its lines in the report when the materials' lookup did
not. `ies.Lookup` says why a file was not found when the walk stopped. `convert/ies.py` `_Numbers` reads tokens
with `_TOKEN.search(data, at)`; counts are checked against the tokens left by counting at most that many.

**Tech Stack:** Python 3.11, unittest, Blender 4.2 / 4.5 / 5.2 headless.
