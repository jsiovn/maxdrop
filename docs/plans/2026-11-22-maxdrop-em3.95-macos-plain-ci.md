# Plain tests on macOS in CI Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the plain-Python job of `.github/workflows/test.yml` on macOS too, so
`tests/test_intake.py` `RenameNew.test_the_native_rename_works` (the `renamex_np(RENAME_EXCL)` binding of
`maxdrop/intake/archive.py` `_load_noreplace`) runs somewhere, and its log shows it ran.

**Architecture:** One extra matrix entry in the existing `python` job (an `include` entry with
`os: macos-latest`, Python 3.13, numpy 2.3.4: Blender 5.2's), not a separate job: the job's steps already gate
the Linux-only installs on `runner.os == 'Linux'`, the `python-gate` job ("Plain Python", required by branch
protection) already waits on every matrix entry, and Ruff stays Linux-only. One Python version is enough (the
bead): the binding does not depend on Python or numpy. A second, verbose run of that one test on Linux and macOS
fails the job unless the test reports `ok`: the main step runs without `-v`, so a skip would pass unseen.

**Tech Stack:** GitHub Actions matrix `include` semantics: an entry whose `os` is not one of the original values
cannot merge into an existing combination without overwriting it, so it is added as a new combination with only
the keys it names (all three named).

Bead: maxdrop-em3.95. Batch 1.0.2, part D (maxdrop-6n0.4).

## Pre-scan of macOS risks (read, not run)

- `tests/test_intake_external.py` `test_real_executable` writes ELF magic off Windows:
  `external._EXE_MAGIC_POSIX` takes ELF on macOS too (magic only, no loader check). OK.

  insensitivity cannot collide.
- `tests/unit/test_textures.py`: `WINDOWS` gates drive letters and junctions only.
- Temp folder under `/var` (a link to `/private/var`): `external.real_executable` compares `realpath` on both
  sides; the archive's link checks look at the destination itself. Not run here: left to the PR's macOS job.
