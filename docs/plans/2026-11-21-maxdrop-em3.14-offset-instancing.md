# Instances split by object offsets: measurement Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure how many meshes `convert/scene.py` loses to instancing because it keys meshes by (base object
index, object offset), and fix it only if that number matters.

**Architecture:** Measurement first, convert only, plain Python (no Blender): run `convert.scene.read` on corpus
scenes A and B from a scratch script outside the repository (the dev package loaded under a stub package rooted at
`maxdrop/`, as `tools/` does), and count per scene. Cross-check with the oracle dumps of both scenes (3ds Max's own
instance groups and object offsets). The fix (one shared mesh, the offset on a child object) is built only if the
count is significant.

**Tech Stack:** Python 3.9+ (local plain Python), numpy; the corpus scenes and their oracle dumps stay outside the
repository, results are counts only.

---

## Decision rule

Significant = at least one base object in either corpus scene whose mesh nodes have more than one distinct object
offset, i.e. the offset in the mesh key costs at least one mesh. Zero in both scenes, with the oracle showing no
instance group whose members differ in offset: close with the numbers, no code change (the bead's "otherwise"
branch).

## Task 1: Count (scratch script, not committed)

- [x] For each MESH node, take its mesh key without the offset component (`(key[0],) + key[2:]`, which keeps an
  Extrude's modifier index, the UVW Map contexts and the shading entry) and collect the distinct offsets per such
  key. Count: mesh nodes, meshes, meshes if the offset were ignored, base objects with more than one offset, the
  nodes of those, the extra meshes and vertices that costs, meshes with a non-identity offset, bases shared by two or
  more nodes. Same for curves (`key[0]`).
- [x] Split nodes and meshes by base class, to compare like with like against the oracle.
- [x] Oracle: group nodes by instance group (their handle plus `instances`), count groups of two or more and the
  groups whose members differ in `offset_pos` / `offset_rot` / `offset_scale`; per base class, nodes minus
  distinct bases.

- The mesh instancing convert keeps equals 3ds Max's own in both scenes, class by class; no instance group has
  members with differing offsets. The offset in the key costs nothing here.
- The bead's 343 / 339 and 1,625 / 1,254 (2026-11-15) are now 363 / 359 and 1,629 / 1,258: scene A's 20 extruded
  shapes and scene B's 4 boxes became meshes since (each its own base object, no instances).
- Decision: not significant. No code change; the bead closes with these numbers. A scene with instances whose
  pivots were moved apart would still get one mesh per offset (the documented behaviour of `convert/scene.py`);
  nothing in the corpus does it.
