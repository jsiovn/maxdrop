# Bezier and TCB keys between two keys Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When frame 0 lies strictly between two Bezier, TCB or Smooth Rotation keys, `reader/controllers.py`
gives 3ds Max's value from the key records' tangents instead of a linear interpolation and the KEYS_INTERPOLATED
issue (maxdrop-em3.102).

**Architecture:** `_keyframe` reads the two key records around time 0 whole (flags and every float) and hands them
to `_between`, which evaluates the class's curve; where the curve is not known it returns None and the linear
interpolation with the issue stays. A new fixture `controllers_tangents` (controllers.max is 940 KB of the 1 MB
budget) shows every case, and its oracle pins it.

**Tech Stack:** 3ds Max 2020 (`3dsmaxbatch.exe`, probes outside the repo), plain Python `unittest`, Blender 4.2.23 /
4.5.16 / 5.2 headless.

## Facts measured (probes in a scratch folder, 2026-11-22)

Three batch probes: Point helpers with each class, keys straddling frame 0, every node sampled every 2.5 frames and
at ticks -1, 1, 7, 33, 160, 799; candidate formulas fitted in Python against the samples (within the 6 digits
MAXScript prints, ~5e-5 on values in the tens).

Key records (float offsets after `i32` time and `u32` flags; n = value floats):

| Class | Record |
| --- | --- |
| Bezier Float / Position / Scale (n 1, 3, 7) | value, in tangent, out tangent, in length, out length, n floats each (Position: 3 floats more, zero) |
| TCB Float / Position / Scale | value, tension, continuity, bias, ease to, ease from (the UI's values: (x - 25) / 25 and x / 50), in tangent, out tangent (n each) |
| TCB Rotation | quaternion, the five TCB values, axis and angle turned from the previous key, in control quaternion, out control quaternion |
| Smooth Rotation | quaternion, in control, out control (equal), two identity quaternions |

- Bezier tangents are value per tick, the in tangent pointing back (MAXScript shows them x 30, a scale's x 3000);
  every tangent type (smooth, linear, fast, slow, auto, custom) stores its computed tangent: the curve needs no type
  rule. Flags: in type bits 7-9, out type bits 10-12 (1 linear, 2 step, 5 custom and auto, 0 smooth, 3 fast,
  4 slow), `0x8000` constant velocity, `0x100000` free handle. Length -1 = a third.
- Bezier segment = the cubic through (t0, v0), (t0 + lo dt, v0 + out lo dt), (t1 - li dt, v1 + in li dt), (t1, v1),
  its time curve solved for t: every non-free key within 5e-5 (lengths 0.6 / 0.15 and per axis included), but
  the reader and 3ds Max differ by up to 8.5e-4 next to a steep key and by ~1e-4 between auto keys (cause not known).
- Step out of the earlier key or into the later: the earlier key's value up to the later key.
- Free handle: neither length as a fraction of the segment nor as frames fits (2e-2 off): stays an issue.
- Constant velocity on a Bezier Float changes nothing; not probed on Position / Scale: stays an issue there.
- TCB: Hermite with the stored tangents (value per segment), at the fraction eased with the earlier key's ease from
  and the later key's ease to (3D Studio's ease); the stored tangents equal Kochanek-Bartels (two keys: (p1 - p0)(1 -
  tension)). TCB Scale's components alike (axes identity in every probe).
- TCB Rotation: squad(q0, out control of the earlier key, in control of the later, q1) at the eased fraction;
  Smooth Rotation the same without ease. Its slerps keep the stored signs (no shorter-arc flip): a 270 and a 200
  degree turn match only that way.
- Linear Rotation 270 degrees between two keys also turns the long way (the stored quaternion keeps the sign): the
  reader's shorter-arc slerp was wrong there (Open item of docs/FORMAT.md).
