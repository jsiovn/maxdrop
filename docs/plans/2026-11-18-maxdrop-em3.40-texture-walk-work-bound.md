# Texture lookup: a bound on work, not only on entries kept — Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the texture lookup (`maxdrop/convert/textures.py`) reads at most `max_entries + 1` directory entries per
rule, whatever the size of the folders it lists, and the SIBLING rule's listing of the scene folder and its parent
counts against the SIBLING budget (bead `maxdrop-em3.40`).

**Architecture:** today `_entries` keeps `budget + 1` entries with `heapq.nsmallest`, but `os.scandir` still yields
every entry of the folder; `_named` (SIBLING) lists two folders in full, uncounted. The fix stops reading a listing
once the rule's budget is gone:

- `_entries(folder, limit)` reads at most `limit` entries (`itertools.islice`) and sorts them by name. A folder
  that has no more entries than the budget left is listed in full and sorted by name, as before. A larger folder
  is the one where the walk stops anyway (truncated, reported): of it, the walk takes the first `budget` of the
  `budget + 1` entries read, in name order; which entries those are follows the order the file system lists them
  (NTFS: name order, so in practice the same entries as before). Deterministic for a given folder.
- `_named(folder, keys, budget)` charges every entry it reads to `budget` and stops at the first entry that finds
  the budget at 0 ("one past the budget", like `_walk`); it returns `(matches sorted by name, cut)`.
- `_roots(rule, budget)` returns `(roots, stopped_folder_or_None)`; SIBLING lists the scene folder, then its parent,
  charging both to the rule's budget; a cut listing stops the rule before any walk, and `_tier` records
  `(SIBLING, folder, max_entries)` in `TextureReport.truncated`, worded by `convert/report.py` like any truncated
  walk.
- No time limit: the count bound caps the entries read and the folders listed per rule (each listed folder is an
  entry already charged, or a root), so the work is proportional to `max_entries`, not to the folder sizes. The
  module docstring says so.

**Tech Stack:** Python 3.11 stdlib (`os.scandir`, `itertools`), `unittest`, no Blender for the unit tests.

```python
def _entries(folder, limit):
    """At most limit entries of folder, sorted by name: the listing is read no further, however many the folder
    has. A folder with more entries than limit is where the walk stops (truncated); which of its entries come
    first then follows the file system's order (name order on NTFS)."""
    try:
        with os.scandir(folder) as it:
            return sorted(itertools.islice(it, max(limit, 0)), key=lambda e: e.name)
    except (OSError, ValueError):
        return []


def _named(folder, keys, budget):
    """(the entries of folder whose name_key is in keys, sorted by name; True when the listing was cut). Every
    entry read is charged to budget (a one-item list); the listing stops at the first entry that finds it at 0."""
    found = []
    try:
        with os.scandir(folder) as it:
            for e in it:
                if budget[0] <= 0:
                    return sorted(found, key=lambda x: x.name), True
                budget[0] -= 1
                if name_key(e.name) in keys:
                    found.append(e)
    except (OSError, ValueError):
        pass
    return sorted(found, key=lambda x: x.name), False
```

`_roots(rule, budget)` -> `(roots, stopped)`; SIBLING loops over `dict.fromkeys((scene_dir, parent))`, returns
`(roots, folder)` at the first cut; `_tier` takes `roots, stopped = self._roots(rule, budget)`, walks only when
`stopped is None`, records one truncation either way.

## Revision after review

`_roots` is a generator: SIBLING lists the scene folder, walks its `maps` / `textures` folders, and only then lists
the parent with the budget left, so a crowded parent (a download folder) cannot spend the budget the scene folder's
own maps need. A cut listing is yielded as `(folder, None)`; `_tier` records it like a cut walk. Test:
`test_a_crowded_parent_does_not_hide_the_scene_folders_maps` (fails on the first version, `cb967a6`).
