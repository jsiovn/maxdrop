# Standard shaders and Physical ids only a probe covered: fixture standard_shaders Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A committed fixture, `standard_shaders`, holds one Standard box per shader (Anisotropic, Blinn, Metal,
Multi-Layer, Oren-Nayar-Blinn, Phong, Strauss, Translucent) and two Physical Material boxes that set the ids no
fixture set (5 roughness_inv, 37 thin_walled, 52 emit_luminance, 61 coat_color, 63 coat_roughness_inv, the maps
101-133, their switches 151-183, 230 bump_map_amt); the shader ClassIDs move into `reader/classids.py` and the
rules are checked against the file.

**Architecture:** `tools/fixtures/standard_shaders.ms` saves ten Editable Poly boxes. Each Standard material sets
diffuse, specular color, specular level, glossiness, self-illumination amount *and* color to its own values, with
`useSelfIllumColor` on for Blinn, Metal, Oren-Nayar-Blinn and Translucent and off for the others (so both
branches of the rule run); Multi-Layer's second layer and Translucent's translucent color hold look-alike values
the rule must not read. The Physical boxes: `FixturePhysicalMaps` (every map slot the rule reads, the
transparency map switched off, roughness and coat roughness inverted, thin-walled, an emission color map,
luminance away from 1500, a bump amount) and `FixturePhysicalOff` (the same slots, the other switches off). Maps are Checker /
Noise (no file paths). The generic raw-parameter parity (`test_materials.py`) checks the reader against the
oracle; new `test_convert_materials.py` classes check each IR against values computed by hand from the script, and
check that the ids of `SHADERS`, Strauss and `physical_mtl` name the expected parameters in the fixture's oracle
(independent of `SHADERS`, so a wrong id fails).

**Tech Stack:** MAXScript (3ds Max 2020, `3dsmaxbatch.exe` with the ViewCube / solid-background wrapper), plain
Python `unittest`, Blender 4.2 / 4.5 / 5.2 headless.

Bead: maxdrop-em3.23

Found with the fixture (3ds Max 2020, `C:\maxdrop_fixtures\probe\em3_23\slots.max`, outside the repo):

- A Standard material's block 3 tables follow the shader's map channels (`getSubTexmapSlotName` and the saved
  `maps` table agree): Blinn / Phong / Metal 1 diffuse, 2 specular, 3 level, 4 glossiness, 5 self-illumination,
  6 opacity, 8 bump, 9 reflection; Anisotropic 4 level, 5 glossiness, 8 self-illumination, 9 opacity, 11 bump, 12
  reflection; Oren-Nayar-Blinn and Translucent 3 glossiness, 4 level, 10 bump, 11 reflection; Multi-Layer 4-8 the
  first specular layer, 14 self-illumination, 15 opacity, 17 bump, 18 reflection; Strauss 0 color, 1 glossiness,
  2 metalness, 3 opacity, 5 bump, 6 reflection. The rule reads Blinn's channels for every shader: bug
  maxdrop-em3.104 (not fixed here; the fixture keeps the Standard materials without maps, which the current rule
  would misread).
- The amounts of channels without a map keep, in the file, the layout of the material as created (Blinn's: bump
  0.3 at 8), while 3ds Max answers its shader's (Anisotropic 0.3 at 11). `test_materials.py` skips those
  (Parity.stale), and a Physical Material's mapM0 ... mapM20 (250-270, saved empty; 3ds Max answers the map at
  id - 150).
- Anisotropic, Oren-Nayar-Blinn, Multi-Layer and Translucent store their diffuse in ambient whatever is set.
- The class directory names the shaders Phong, Blinn, Metal, Anisotropic, Oren-Nayar-Blinn, Multi-Layer,
  `Translucent Shader`, Strauss.
- Physical Material's 0x0013 table lists its maps at slot 0: no owner_slots.py entry.
- Review: the by-hand values could not tell apart Physical ids holding the same value in both materials; physical_mtl
  now reads them from `PHYSICAL` (keyed by the oracle names, switches at `PHYSICAL_SWITCH` = 50), which the test
  checks against the oracle. Swapped ids, flags or a wrong offset all fail.
- Parity compares 1633 values (floor 1600). Red check: a wrong Anisotropic level id or a wrong Physical switch id
  fails the new tests.

Not in this bead (debt maxdrop-em3.105): the rule ignores diffuseLevel (Anisotropic, Multi-Layer, Oren-Nayar-Blinn,
Translucent), and the defaults it takes for a missing shader parameter are Blinn's for every shader (the other
shaders default to diffuse 127.5 grey, glossiness 25 / 50 / 25 / 30 / 20 %, Anisotropic and Multi-Layer level 5 %).
The fixture keeps diffuseLevel at 100.
