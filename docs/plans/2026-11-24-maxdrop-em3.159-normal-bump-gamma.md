# Normal and bump images by the scene's gamma Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** decode a normal map's and a bump map's image the way V-Ray 5.2 (and Corona 12) do, gamma on and off, instead
of keeping every such image Non-Color (bead maxdrop-em3.159).

**Architecture:** the renders below show that a normal or bump input takes an image by the data rule em3.122 measured
for glossiness and opacity: a Bitmap is decoded by its gamma with the gamma on (automatic and 2.2: the file input
gamma) and read as stored with an override of 1.0 or with the gamma off; a CoronaBitmap by its own gamma in both
modes; a VRayBitmap by its transfer function, except that under a normal map (VRayNormalMap, Normal Bump) V-Ray reads
it as stored whatever its transfer function. `colorspace` treats NORMAL and BUMP as DATA; `_vray_image` keeps a
VRayBitmap normal Non-Color; CoronaNormal's "add gamma to input" (measured: re-encodes by 1 / 2.2 with the gamma on,
nothing with it off) is converted for an image input. The builder needs no change: it already draws an image's color
space and its gamma (`drawn_gamma`) on every input.

**Tech Stack:** 3ds Max 2020 + V-Ray 5.2 + Corona 12 (`3dsmaxbatch`, scratch MAXScript), plain Python `unittest`,
Blender 4.2 / 4.5 / 5.2 headless.

## Measurement (outside the repository: `C:\maxdrop_fixtures\probe\em3_159\`)

Self-authored 8-bit PNGs without a gAMA chunk: `flat.png` (128, 128, 255), `tilt.png` (180, 100, 220), `ramp.png`
(256 x 16, grey = x). Planes 40 x 40 under an orthographic top camera, VRayMtl (CoronaLegacyMtl in pass 4) white,
normals read from VRayBumpNormals (CGeometry_NormalsShading for Corona; both store (n + 1) / 2), saved from the VFB
and read in headless Blender (`read_vray.py`). Gamma off (`#none`) and on (`#gamma`, file input 2.2). Bump: the ramp
tiled 10 times in U; the slope is read at a tooth's 0.25 and 0.75 (stored: equal; decoded by 2.2: about 1 : 3.7).

Normal (tangent space; `flat` stored is (0, 0, 1), decoded by 2.2 (-0.44, -0.44, 0.78), 38.5 degrees):

| image under VRayNormalMap / Normal Bump | off | on |
|---|---|---|
| Bitmap auto / 2.2 | stored | decoded (2.2: within 0.3 degrees of the sRGB curve) |
| Bitmap 1.0 | stored | stored |
| CoronaBitmap auto / 2.2 | decoded | decoded |
| CoronaBitmap 1.0 | stored | stored |
| VRayBitmap None / sRGB / From 3ds Max | stored | stored |

Bump (slope at 0.25 / 0.75 of a tooth, as the tilt's x):

| height image | off | on |
|---|---|---|
| Bitmap auto / 2.2 (bump slot, VRayNormalMap bump input) | 0.030 / 0.030 stored | 0.015 / 0.050 decoded |
| Bitmap 1.0 | stored | stored |
| CoronaBitmap auto / 2.2, VRayBitmap sRGB | decoded | decoded |
| CoronaBitmap 1.0, VRayBitmap None | stored | stored |
| VRayBitmap From 3ds Max under VRayNormalMap's bump input | stored | decoded |
| VRayBitmap From 3ds Max directly in the VRayMtl bump slot | decoded | decoded |

Corona 12 (pass 4, CoronaNormal and a CoronaLegacyMtl bump slot): the same rule for Bitmap and CoronaBitmap, normal
and bump. CoronaNormal "add gamma to input": with the gamma on the input re-encoded by 1 / 2.2 (a Bitmap or
CoronaBitmap auto shows as stored, a 1.0 one brighter than stored); with the gamma off no effect.

V-Ray bends a decoded tilt back to 44.2 degrees (from 59.2): its shading-normal limit, not a decode (the azimuth is
the decoded one).
