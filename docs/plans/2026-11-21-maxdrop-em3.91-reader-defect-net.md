# Reader defect net (TypeError / KeyError) Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A TypeError or KeyError raised while reading a `.max` (reader + scene description) reports the file as
not imported, with the traceback in the console, instead of ending the operator with a traceback.

**Architecture:** The net goes around the reading only, not into `ops._UNREADABLE`. `_read_scene` and
`_preflight` catch `_DEFECTS = (TypeError, KeyError)`, print the traceback and re-raise / report it as
`_ReadDefect`, a private `ValueError` (so already one of `_UNREADABLE`) whose message names the type. The fuzz
harness mirrors the reader path, not `ops`, and keeps counting those errors as escaped.

**Tech Stack:** Python 3.11, Blender 4.2 / 4.5 / 5.2 headless (`tests/blender/run.py`).

---

## Decision: why not add TypeError / KeyError to `_UNREADABLE`

`except _UNREADABLE` in `_Run.steps` wraps all of `_scene_steps`: the read, the build, and the report and axis
fix-up after `made.append(cols)`. A TypeError / KeyError there is a Blender-side defect of the build; reporting it as
"Not imported: x.max" would hide it (the objects of a post-build failure may even stay). So only the bpy-free
reading (`_read_scene`: reader, `convert.scene.describe`, the asset table, saved views; `_preflight`) gets the
net. The material conversion already catches any Exception on its own. `convert.scene.Cancelled` and
`GeneratorExit` are neither type and pass unchanged. Only the two types the bead names: AttributeError and others
stay escapes (not widened).

`_ReadDefect` is not a `MaxFileError`: the file is not known to be damaged, the reader is.

Reason text: `str(KeyError(5))` is `"5"`, so the message carries the type:
`a defect in MaxDrop's reader (KeyError: 5), see the console`.
