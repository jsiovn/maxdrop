# Scene packs: stale staging, destination race, entry count first Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `maxdrop/intake/archive.py` cleans up the staging folders a crash left behind, never fails or
overwrites when two unpacks race for the same folder, refuses a zip with too many entries before `zipfile`
builds its directory, and treats a Windows junction as a link.

**Architecture:** Four small changes in the one module, each with its own test in `tests/test_intake.py`:

1. `_remove_stale_staging(parent)`: before `tempfile.mkdtemp`, remove folders in the staging parent whose name
   starts with `STAGING_PREFIX`, that are real folders (not links, not junctions) and whose mtime is older than
   `_STALE_SECONDS` (6 h; an unpack is stopped after `Limits.seconds`, 15 min by default). Best effort: every
   error is ignored. Nothing else in that folder is looked at.
2. Reserve the destination with `os.mkdir`: `_destination` also returns the candidate folders from the chosen
   one on; after the staged files pass `_check_staging`, `_reserve` creates the first candidate that does not
   exist (`FileExistsError` -> the next one; an existing folder is never written into), the files move into it
   one by one (maps first, the `.max` after them, the marker last: a parallel probe never sees a `.max` without
   its maps, and only a complete folder carries the marker), then the empty staging folder is removed. A failure
   after the reservation removes the reserved folder (this code created it). The pack folder of a several-scene
   pack (`container`) is created the same way: when its `os.mkdir` meets an existing folder, `_destination` is
   asked again (bounded), since a racer's folder may be one to reuse.
3. Entry count from the end records: `ZipBackend.entry_count(path, cap)` reads the end-of-central-directory
   record (and the zip64 locator + record directly before it, as `zipfile` does), refuses when the declared
   count exceeds `cap`, and also counts the central directory records themselves (46-byte headers, skipping
   name / extra / comment, constant memory, stopping at `cap + 1`): `zipfile` walks the directory by its size,
   not its count, so a lying count would otherwise pass. `_read_entries` calls it (when the backend has it)
   before `backend.names`. One message for both checks: `<archive> lists more than the <n> entries MaxDrop
   reads. Extract it by hand.`
4. `_is_link(path)`: `os.lstat`, a symlink, or on Windows a reparse point whose tag is a junction
   (`IO_REPARSE_TAG_MOUNT_POINT`) or a symlink. Not any reparse point: OneDrive placeholders are reparse points
   too and must stay searchable. Used by `_probe`, `_destination` (pack folder) and `_find_copy` (folders
   only), and by the stale-staging cleanup. Same check on every Python (3.12's `os.path.isjunction` is not used
   by this code either).

`CHANGELOG.md` gets a line under `## [Unreleased]` (the epic's rule: no version bump).

**Tech Stack:** plain Python 3.9-3.13 (`os`, `stat`, `struct`, `zipfile`), `unittest`.
