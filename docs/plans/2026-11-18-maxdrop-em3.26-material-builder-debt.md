## File map

- `maxdrop/build/materials.py`
  - `crop_axes(mapping)`: per axis `'MIRROR'` (mirror on: wins over tile, as in 3ds Max), `'REPEAT'` (tile), or
    `'CLIP'`.
  - `extension(mapping, crop)`: with a crop, `'CLIP'` when placed or any axis clips, else `'EXTEND'` (the
    coordinates stay inside the crop rectangle: no bleed from the opposite edge).
  - `texture_node`: the crop's wrap per axis. Both axes REPEAT: one Vector Math FRACTION (as before). Otherwise
    Separate XYZ -> per axis a Math node -> Combine XYZ: REPEAT `WRAP` (1, 0), MIRROR `PINGPONG` (scale 1), CLIP:
    placed: nothing (the TEXTURE mapping already sends a coordinate outside 0..1 out of the image); cropped:
    `FLOOR` then `MULTIPLY_ADD` (`c + K * floor(c)`, `K = 1 / size + 1`), which keeps 0 <= c < 1 and pushes any other
    c out of the image after the crop mapping (worked out: c < 0 lands below 0, c >= 1 above 1).
  - Map channel 0 (vertex color as UVW: build/objects makes no such layer): `issue(label, "map channel 0 (vertex
    color) not imported: <name> on UV channel 1")` and the image uses channel 1; a normal map on channel 0 the
    same, its tangents from the default UV map.
  - `image_has_data(path)`: plain-Python header check (no decode): False for an empty file, or for a file whose
    extension names a format with a signature (png, jpg/jpeg/jpe, bmp, tif/tiff, exr, hdr, dds, psd, webp,
    jp2/j2k/j2c, sgi/rgb/rgba/bw, cin, dpx) and whose first bytes match no image signature Blender reads. Other
    extensions (tga has no signature) pass. `MaterialBuilder.image` checks it before loading: `texture not loaded:
    <name> (no image data)`, no datablock, the node without an image (as a file that does not load).
  - `MaterialBuilder.make`: an exception while the tree is built removes the half-made material, adds `material
    not built: <name> (<Type>: <message>)` to the issues and returns None (an empty slot); the traceback goes to the
    console with the `MaxDrop:` prefix.
  - Docstring: the four rules.
- `maxdrop/ops.py`
  - `_import_scene`: `_material_slots` in `try/except Exception`: on failure slots None, the traceback to the
    console, and `add_materials(..., build_issues=[("materials", "not converted (<Type>: <message>): the scene is
    imported without materials")] + builder.issues())`; materials counted without the None entries.
  - Header: dated "Modified for MaxDrop" line.
- `tests/blender/run.py`
  - `check_builder_debt()` (new, run from `main` with the others), hand-made IRs:
    1. crop, tile off both axes: Separate XYZ -> FLOOR/MULTIPLY_ADD per axis -> Combine XYZ -> Mapping POINT;
       extension CLIP; K = 1/w + 1.
    2. crop, mirror U, tile V: PINGPONG on X, WRAP on Y; extension EXTEND.
    3. crop, tile both: FRACTION; extension EXTEND.
    4. placed, mirror both (the existing wiring case): PINGPONG both, Mapping TEXTURE; extension CLIP.
    5. channel 0 image and normal map: no UV Map node named `UVChannel_0`, normal map uv_map empty, one issue per
       image naming channel 0.
    6. a `.png` holding text: node without image, no datablock, issue `(no image data)`; `image_has_data` on an
       empty file, a real PNG, a `.tga` of junk (True).
    7. `make` on an IR whose tree raises (a texture graph root of an unknown type whose build raises, by
       monkeypatching `_Tree.build`): returns None, no material left, issue `material not built`.
  - Operator case: `_material_slots` monkeypatched to raise on `vray_maps.max`: result FINISHED, objects
    imported, no materials, the report text has `not converted` under Material issues.
  - Update the existing expectations that pinned the old crop graph: `check_builder` ("a placed crop clips":
    stays CLIP), `check_builder_wiring` (placed crop: PINGPONG chain instead of FRACTION), `texmap_rules`
    place_crop.png (mirrored -> PINGPONG nodes, not the MIRROR extension).
- `docs/SUPPORT.md`: Bitmap row: tile and mirror per direction with cropping; map channel 0 reported; a texture
