# maxdrop-em3.136: VRayOverrideMtl and Double Sided with a sub-material switched off, rendered

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make the wrapper peel do what V-Ray 5.2 renders when a VRayOverrideMtl or Double Sided sub-material is
switched off, instead of maxdrop-em3.103's fall-through to the next sub-material.

**Architecture:** `maxdrop/convert/materials.py` `WRAPPER_SWITCHES` loses its VRayOverrideMtl and Double Sided
entries (the switch loop stays for CoronaRaySwitchMtl); `_sub` names a Double Sided whose facing material is off in
the report (the scanline renders that side black). Docs say what was measured.

**Tech Stack:** Python 3.11 (plain, no bpy), 3ds Max 2020 + V-Ray 5.2 batch renders for the measurement.

---

## Measurement (done before the plan; scene and renders outside the repo)

3dsmaxbatch, self-authored scene of 40x40 planes under a top camera, gamma off, background grey 40. V-Ray
sub-materials VRayMtl (diffuse black, self-illumination = the color), scanline ones Standard (self-illumination
100); a spherical dome (V-Ray) / ambient white (scanline) so a default material would not be black (control: grey).
Colors: base / facing red, GI green, reflect blue, refract yellow, shadow magenta, back cyan. The switches were read
back from the saved file with the MaxDrop reader (params 1..9 / 2, 3 as set).

| case | V-Ray 5.2 | scanline |
|---|---|---|
| VRayOverrideMtl all on | base | (not a scanline material: black) |
| baseMtl_on off; then GI off too; all five off; base off + GI empty | base, every time | - |
| base empty (switch on), GI set | black (hit) | - |
| Double Sided both on | facing / back | facing / back |
| map1Enabled off | facing / back | black / back |
| map2Enabled off | facing / back | facing / black |
| both off | facing / back | black / black |
| material1 empty | front not rendered (alpha 0) / back | black / back |

Pass 1 (Standard self-illumination in V-Ray, which rendered black) is no evidence. VRayCarPaintMtl and
VRayCarPaintMtl2 as created: texmap_base_bump_multiplier 30.0 both (V-Ray 5.2 has VRayCarPaintMtl2).

## Decision

- V-Ray ignores both classes' switches: the peel does too (VRayOverrideMtl is V-Ray's own; the rules are measured
  against V-Ray 5.2). The base / facing material is used whatever its switch says.
- Double Sided with map1Enabled off: a report issue, once per wrapper object and only when the facing material is
  the one drawn (not when it is empty or not a material), that the scanline renders that side
  black (`_issue_once`: `peel` caches by top index, so `_sub` can run twice on one wrapper).
- Out of scope, filed as a P4 tech-debt bead under maxdrop-6n0.6: the empty-slot fall-through (an empty
  VRayOverrideMtl base renders black, an empty Double Sided material1 renders nothing in V-Ray / black in scanline;
  the other wrappers' empty slots were not rendered), and CoronaRaySwitchMtl's direct-off fall-through, which rests on
  the reading V-Ray just refuted for VRayOverrideMtl.
- Car paint: record 30.0 in docs/FORMAT.md and reword the stale comment in `_car_paint`; the missing-value default
  (100) stays (what a file without the parameter means was not measured; its test would sit outside Wrappers).
