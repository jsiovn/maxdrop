# Gamma-off float dome texture as a light Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure how V-Ray 5.2 lights and shows a dome texture that is a float file (EXR) in a gamma-off scene,
compare it with Blender renders of MaxDrop's import, and make `convert/lights.dome_texture` follow the rule the
numbers pick (bead maxdrop-em3.166).

**Architecture:** A local probe (outside the repo, `<probe>/em3_166/`): self-authored EXRs and PNGs, a MAXScript
that builds and renders each scene in 3dsmaxbatch (V-Ray 5.2, linear color mapping, gamma 1, GI off, EXR out) and
saves the `.max`, a Blender script that imports each `.max` with the dev package, renders Cycles and reads the same
pixel blocks under each candidate rule (switching the World image's color space / Gamma node in the script, no code
edit). The decision then goes into `dome_texture` (only what a DomeTexture image's gamma and color space can say),
its report line, its tests and the docs.

**Tech Stack:** 3ds Max 2020 + V-Ray 5.2 (3dsmaxbatch), Blender 5.2 headless (4.2 / 4.5 at the end), Python 3.11
syntax.

---

## Targets and candidates

- Gamma on: Blender linear = V-Ray's internal value (the probe gate: the unchanged importer agrees within 0.02).
- Gamma off: Blender linear = srgb_to_linear(V-Ray's internal value), extended above 1 (the display-referred scene).
- Candidates a `dome_texture` image can express for a float file with the gamma off:
  - A, own decode (today): the EXR linear.
  - B, the material rule (`texmaps._shown`): the EXR in sRGB (Blender's extended curve), as on a material.
- Prediction: the target is a nonlinear function of the summed light, a per-texel decode matches it only for a
  uniform sky. Uniform 0.5 / 4.0: B exact on the white floor, A off (0.5 vs 0.214, 4.0 vs ~25). A small bright
  sun: B multiplies the sun by roughly L^1.4 (orders of magnitude), A stays near the target. The grey plane: the
  decoded albedo times the decoded light is not the decode of the product (B ~10 % off at 4.0).
- Decision criterion (fixed before the numbers): the rule whose worst white-floor ratio (Blender / target) over the
  float rows is nearest 1 on a log scale; a rule more than a factor 2 off on any float row is out. A miss no
  `dome_texture` rule can remove (non-uniform sky, the product) is documented with its numbers, not tuned away.
  A rule needing `build/world.py` (for instance a Light Path split: the camera sees B, light uses A) or the
  image's pixels is filed as a P4 tech-debt child of maxdrop-6n0.6, not done here.

## Probe rows

Each scene alone, VRayLight dome (multiplier 1, default units, spherical, invisible off), a white diffuse floor
(VRayMtl diffuse 255, no reflection) and a grey plane (diffuse 128) side by side, coplanar, facing up; a camera that
sees both and a band of sky. Gamma off and on (input 2.2) for every row:

1. EXR uniform 0.5 (VRayBitmap spherical, Auto)
2. EXR uniform 4.0
3. EXR sun patch: dim sky 0.2, a patch of 2000 over a known solid angle at a known elevation
4. PNG 128 grey, VRayBitmap Auto (the 8-bit rule of em3.123: gamma 5.0 drawn)
5. no texture, white dome multiplier 1 and 0.5 (control: what the importer does with an untextured light)
