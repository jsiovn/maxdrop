# intake/archive.py crash and race leftovers Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settle the five rare leftovers bead maxdrop-em3.81 lists in `maxdrop/intake/archive.py`: each item ends
either changed with a test, or accepted with the reason written here and in the bead notes.

**Architecture:** Nothing new is removed by prefix and age alone where it may hold a scene: a `RECLAIM_PREFIX`
folder is cleared only through the stale-reservation judgement (`_clear_stale_reservation`, file by file, one of
two clears wins); a folder taken aside under `STAGING_PREFIX + "reclaim-"` that holds a marker or a `.max` was
filled anew, so stale-staging cleanup renames it to a `RECLAIM_PREFIX` name instead of removing it. `_create` takes
a name a clear just freed with the mkdir fallback when the rename is refused. Every unpack of a several-scene pack
cleans stale staging beside the pack folder.

**Tech Stack:** plain Python 3.11, unittest.

---

## Items

1. **Reclaim folders never cleaned** (changed). `unpack` runs `_clear_reclaimed(parent, ident)` right after
   `_remove_stale_staging(parent, limits)`: every `RECLAIM_PREFIX` folder in `parent` goes through
   `_clear_stale_reservation(folder, ident)`. One holding a stale reservation of this pack and nothing but its
   maps (the half-filled folder of an unpack that then failed) is removed; anything else stays (a marker, a
   `.max`, a recent reservation, another pack's reservation, a file this code never wrote). Accepted: a reclaim
   folder holding a complete scene stays for good (it is not a candidate name, so it is never reused); it is
   not named in the unpack result (that would widen the operator's report for a race that needs three unpacks
   of one pack at once).
2. **`_create` fallback** (changed in part). After `clear(folder)` freed a name, a refused rename now falls back to
   mkdir + fill like the first try, and any `OSError` of that mkdir (Windows: the old folder still pending
   delete gives `PermissionError`, not `FileExistsError`) skips the name instead of stopping the unpack. Accepted:
   the fallback's own window (mkdir, then the first write) stays; a folder cannot appear filled without a rename,
   and the fallback runs only when that rename is refused.
3. **Crash between the clear's renames** (changed). `_remove_stale_staging` never removes a
   `STAGING_PREFIX + "reclaim-"` folder holding a `MARKER` or a `.max`: a stale folder has neither (see
   `_stale_reservation`), so it was filled anew; it is renamed to a `RECLAIM_PREFIX` name (best effort; left as
   it is when that fails) and then judged as item 1. Other staging folders are removed as before, a pack
   folder's staging holding the pack marker included.
4. **POSIX look-then-rename** (accepted). `renameat2(RENAME_NOREPLACE)` through ctypes was considered. Not
   shipped: this batch has no Linux to run it on (WSL does not start on this machine, no CI run from an executor
   session), and an unrun syscall wrapper is worse than a documented, harmless race: an empty folder someone
   makes in the instant between the look and the rename is replaced (no file is lost; the folder now holds the
   unpack). macOS (`renamex_np`) likewise. `_rename_new`'s docstring says so already; it gains the reason.
5. **Staging beside a several-scene pack folder** (changed). `_remove_stale_staging(dest_parent, limits)` runs for
   every unpack of a several-scene pack that writes (not only when the pack folder is created).
   `StaleStaging.test_only_the_staging_parent_is_cleaned` asserted the old behaviour; it is replaced.
