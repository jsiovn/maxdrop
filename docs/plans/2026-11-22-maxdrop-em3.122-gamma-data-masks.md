# Data constants and image masks by the scene's gamma Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make a constant or an image on a material data input (roughness from glossiness, metallic, opacity) and a
mask inside a color graph give the number V-Ray 5.2 renders, gamma on and off (bead maxdrop-em3.122).

**Architecture:** a texmap's value does not depend on the slot it drives (measured below): V-Ray uses that internal
value for a data input; with the gamma on it is linear, with it off it is display-referred, so a color (and a mask
mixing colors) is decoded in Blender while a data number is used as it is. `convert/texmaps.py` gets a fifth kind,
MASK: a float sub-graph inside a COLOR (or MASK) graph (Mix, CoronaMix and Composite masks; the Corona layer mask).
DATA keeps the material's float inputs and the masks under them. Constants: COLOR the linear color, MASK the scene's
rule of the mean (as today), DATA (and BUMP) the mean of the swatch as stored. Images: MASK and DATA take the color
rule of their gamma (decoded) except a DATA image whose map reads its pixels as stored in this scene (a Bitmap, a
VRayBitmap From 3ds Max, with the gamma off): Non-Color. The builder applies a LINEAR image's gamma also in FLOAT.

**Tech Stack:** 3ds Max 2020 + V-Ray 5.2 (`3dsmaxbatch`, scratch MAXScript), plain Python `unittest`, Blender 4.2 /
4.5 / 5.2 headless.

## Measurement (outside the repository: `C:\maxdrop_fixtures\probe\em3_122\`)

`probe.ms` and `probe2.ms`: planes rendered by V-Ray 5.2 with GI and default lights off, color mapping linear, gamma
1; a 128 grey 8-bit PNG (no gAMA chunk); the VRayMtlReflectGlossiness element (through the VFB) for glossiness, the
render alpha for opacity, `getPixels ... linear:true` (V-Ray's internal value). Gamma off (`#none`) and on (2.2,
file input 2.2).

| Map | on | off |
|---|---|---|
| glossiness: VRayColor 64 / plain 0.251 / VRayColor red | 0.251 / 0.251 / 0.333 | the same |
| opacity: VRayColor 64 / VRayColor red / Mix black-white by VRayColor 64 | 0.251 / 0.333 / 0.251 | the same |
| opacity: Mix grey 40 -> 220 by VRayColor 128 | 0.511 | 0.511 |
| glossiness, opacity or mask: Bitmap auto / 2.2 / 1.0 | 0.2195 / 0.2195 / 0.502 | 0.502 / 0.502 / 0.502 |
| glossiness or mask: CoronaBitmap auto / 2.2 / 1.0 | 0.2195 / 0.2195 / 0.502 | the same |
| glossiness or mask: VRayBitmap sRGB / From 3ds Max / None | 0.2159 / 0.2195 / 0.502 | 0.2159 / 0.502 / 0.502 |
| emission: Mix grey 40 -> 220 by VRayColor 128 / by the Bitmap auto | 0.511 / 0.312 | 0.511 / 0.511 |

So a data input takes the map's internal value: a swatch as stored in both modes (MaxDrop today decodes it with the
gamma off: 0.051 for the 64), an image decoded by its gamma with the gamma on (MaxDrop today: Non-Color, 0.502). In
a color graph with the gamma off the result is display-referred: Blender needs `srgb_to_linear` of it, so a mask
between black and white is the decoded number: 0.216 for the PNG (MaxDrop today: Non-Color 0.502, shown as 188 where
V-Ray shows 128). Between two colors the mix happens on display values: target `srgb_to_linear(0.511)` = 0.225;
decoding the mask gives 0.171 (today's rule for a constant, kept: exact only between black and white), mixing in
display space would be a builder change (debt bead).
