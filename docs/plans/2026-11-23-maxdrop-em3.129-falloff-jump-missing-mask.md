# falloff_curve: the jump and missing-mask cases in Blender (maxdrop-em3.129) Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Pin in Blender (and against 3ds Max's own numbers) a Falloff curve with two points at one x and a masked
Mix with Use Curve whose mask image is missing.

**Architecture:** Test-only. The fixture script gets a Falloff with a vertical jump (appended after the existing
nodes) and non-zero mix amounts on the two masked Mix maps; the fixture, its oracle and `.curves.jsonl` are
regenerated in 3ds Max 2020. The unit tests compare the convert side with 3ds Max's values; `check_falloff_curve`
in `tests/blender/run.py` checks the Float Curve keeps the jump and the missing-mask factor.

**Tech Stack:** MAXScript (3ds Max 2020, .NET ICurve), Python unittest, Blender 4.2 / 4.5 / 5.2 headless.

---

## Probe (done before the plan)

`C:\maxdrop_fixtures\probe\em3_129\probe.ms` (3dsmaxbatch, outside the repo): `ICurve.Insert` takes two corner
points at x = 32.5 / 64 (y 0.8 then 0.3). Both stay, in insert order, after save and reload (4 points).
`GetValue` gives 0.8 at the jump x itself and 0.79998 at 0.5078, then 0.300011 at 0.50782 and 0.303111 at 0.51.
That is a falling vertical jump. MaxDrop's reader reads the 4 points in that order, and `curve_samples` gives
`(0, 0), (x, 0.8), (x, 0.3), (1, 1)`, the same polyline. So the jump goes into the fixture. The hand-built
`check_curve_step` stays as it is.
