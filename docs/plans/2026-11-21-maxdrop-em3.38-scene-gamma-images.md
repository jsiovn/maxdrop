# Scene gamma: input gamma, gamma-off images, temperature colors Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read images the way 3ds Max reads them under the scene's Gamma/LUT setting. With the gamma on, a Bitmap
with automatic gamma (and a VRayBitmap whose transfer function is From 3ds Max) uses the file input gamma. With the
gamma off, a Bitmap ignores its gamma override. CoronaColor's temperature follows the swatch rule, as VRayColor's
does.

**Architecture:** `convert/colors.Swatches` gets a `file_in` field: the input gamma with the gamma on, 2.2 by
default, so `GAMMA_ON` / `GAMMA_OFF` / `UNKNOWN` are unchanged and `for_gamma` returns `GAMMA_ON` itself for a 2.2
file. `TexmapConverter` reads it through `self.swatches`. ops.py already passes `colors.of_scene(sc)` to both
converters, and that call now carries the input gamma. No new path.

**Tech Stack:** Python 3.11 standard library; 3ds Max 2020 + V-Ray 5.2 (`3dsmaxbatch`) probes; Blender 4.2 / 4.5 /
5.2 headless.

- The 8-bit output: with the gamma on the PNG gets the output gamma (swatch 186), with it off the internal value as
  is (swatch 128). In the LUT session too (128). A gamma-off scene is display-referred: in Blender terms an internal
  value v is srgb_to_linear(v).
- LUT mode is the session's, not the file's. `lut22.max` (Scene chunk 1, Config 0) opens as `#gamma` from a `#none`
  or `#gamma` session and renders like a gamma-on file (swatch 186, PNG 128). A `#lut` session keeps `#lut` for any
  file whose chunk says 1. So no code change: the Scene chunk's 1 is gamma on.
- Corona render: `Corona license not found` in `3dsmaxbatch` (batch.out), as in maxdrop-arp.16. Not measurable on
  this machine. A debt bead is filed.
- Left for that debt bead (measured, not converted, a design choice): with the gamma off, CoronaBitmap (any gamma),
  VRayBitmap Auto / sRGB and an EXR keep their own decode. So their internal value is decoded once more for the
  display (V-Ray shows them darker than MaxDrop does). VRayBitmap None renders 0.502 with the gamma off (as
  stored, like a Bitmap's override 1.0) but stays linear here: changing it would move the vray_texmaps fixture's
  only Linear Rec.709 color image (the Blender found-textures check); Inverse gamma with the gamma off is not
  measured. CoronaColor's HDR color with the gamma off is not measured.

## The rule

Color inputs only (data inputs stay Non-Color, the override not applied):

- Gamma on (`Swatches.linear`, not UNKNOWN's default): Bitmap automatic -> `file_in` (None, i.e. sRGB, when within
  0.05 of 2.2; 1.0 for EXR / HDR as before); override kept. VRayBitmap From 3ds Max (3) -> the same as a Bitmap's
  automatic.
- Gamma off: Bitmap -> None (sRGB) whatever its override; EXR / HDR 1.0 as before. VRayBitmap From 3ds Max -> None.
- Unknown (no chunk): today's behavior (`file_in` 2.2, overrides kept).
- CoronaColor temperature: with the gamma on, unchanged (`corona_kelvin` x multiplier, not clamped). With it off,
  `conv._swatch(lin, kind)` (clamped, decoded; data: the decoded mean).
- Report line: gamma on with `file_in` not 2.2 gets `; images with automatic gamma read with input gamma 1.0`.
