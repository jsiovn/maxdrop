# Node Cast / Receive Shadows Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read a node's Cast Shadows and Receive Shadows flags; an object that casts no shadow in 3ds Max casts
none in Blender (`Object.visible_shadow`), and Receive Shadows off, which Blender cannot express per object, is a
report issue.

**Architecture:** reader/scene.py exposes `Node.cast_shadows` / `receive_shadows` (bits of the u32 in `0x099C`);
convert/scene.py copies them onto `NodeDescription` and raises the receive issue for nodes with a surface;
build/objects.py sets `visible_shadow` on mesh and curve objects. The oracle (layout 13) gains both node flags, so
every fixture checks the reader against 3ds Max.

**Tech Stack:** 3ds Max 2020 (`3dsmaxbatch.exe`, probes in a folder outside the repo), plain Python `unittest`,
Blender 4.2.23 / 4.5.16 / 5.2 headless with an isolated profile.

## Probe (2026-11-22, saves of one change each, `tools/maxdiff.py` A / A2 / B)

- A Box made by MAXScript: `castShadows`, `receiveShadows`, `renderable` all true; `0x099C` = `0x0F00D600`.
- `receiveShadows = false` -> `0x0F00D200` (bit `0x400`); `castShadows = false` -> `0x0F00D400` (bit `0x200`,
  as em3.72 found); both -> `0x0F00D000`. With cast off, `0024#0/0103` also changed by +1 (observed, not chased).
- An Omni: node `castShadows` true, `baseObject.castShadows` false; toggling the node's flag changes only its
  `0x099C` bit `0x200` (FORMAT.md, Lights, already says so). The fixture scripts set only `baseObject.castShadows`.
- A layer's `0x1050` (`0x0B00D600`) carries the same two bits; they matter only for a node whose rendering is By
  Layer, which MaxDrop does not read for `renderable` either: out of scope (debt bead if worth it).

## Decisions

- Node default without `0x099C`: `RENDERABLE | CAST_SHADOWS | RECEIVE_SHADOWS` (a new node's state); the layer
  default stays `RENDERABLE`.
- `visible_shadow` only on MESH and CURVE objects: a light's own switch is `Light.use_shadow`; empties and
  cameras have no surface. Checked on 4.2, 4.5 and 5.2 (`Object.visible_shadow` exists since 3.0).
- Receive Shadows off: one issue per MESH / CURVE node, `shadows: Receive Shadows off: Blender has no per-object
  switch, the object receives shadows` (the report caps the list). Not on lights, cameras, helpers.
