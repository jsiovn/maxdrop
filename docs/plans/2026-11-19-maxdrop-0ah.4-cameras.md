# Cameras: Free, Target, Physical, VRayPhysicalCamera Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The scene's cameras arrive as Blender cameras with 3ds Max's framing (horizontal field of view for the
scene's render aspect, lens shift, orthographic width, clipping), the render resolution is the scene's, and the view
the artist rendered from is `scene.camera`.

**Architecture:** `convert/cameras.py` (no bpy) names a camera's family by ClassID, reads its parameters (the old
ParamBlock and chunks of Free / Target, the ParamBlock2 of Physical and VRayPhysicalCamera, by parameter id), and
turns them into a `CameraDescription` (lens, sensor, shift, clip, ortho scale, issues). It also reads the render
settings (RenderEnvironment) and the saved viewports (Config stream) into a `RenderDescription`. `convert/scene.py`
gives camera nodes the kind CAMERA (keyed like lights), picks the scene camera, and takes the views as an argument
(`read()` and `ops.py` pass them, as they pass the asset table). `build/cameras.py` makes the Camera and sets the
render resolution and `scene.camera`.

**Tech Stack:** Python 3.11 syntax; 3ds Max 2020 + V-Ray 5.2 through 3dsmax-mcp (own instance) for the probes, the
fixture and its oracle; Blender 4.2 / 4.5 / 5.2 headless.

## What 3ds Max 2020 + V-Ray 5.2 store (probed on scratch scenes, maxdiff + renders, not committed)

- Superclass 0x20 (camera). Free Camera `(0x1001, 0)`, Target Camera `(0x1002, 0)`: reference 0 = old ParamBlock by
  index: 0 FOV (radians, horizontal, whatever the FOV type shown), 1 target distance (a free camera's; 0 on a target
  camera), 2 near clip, 3 far clip, 4 / 5 environment ranges, 6 multi-pass effect on, 7 effect per pass, 8 FOV type
  (display only). Chunks of the camera object: 0x268C present = orthographic, 0x2686 present = clip manually, 0x2684
  present = show cone.
- Physical Camera `(0x46697218, 0x28E8008D)`, ParamBlock2 block 0: 0 targeted, 8 target distance (world), 4 film
  width (mm), 5 focal length (mm), 19 specify FOV, 20 FOV (degrees), 7 zoom, 54 lens breathing, 10 specify focus,
  9 focus distance (world), 11 use DOF, 39 / 40 horizontal / vertical shift (percent of the film width), 41 / 42
  horizontal / vertical tilt correction, 44 distortion type, 47 clip on, 48 / 49 clip near / far (world).
- VRayPhysicalCamera `(0x405E3FEE, 0x4F6513BE)`, ParamBlock2 block 0: 8 targeted, 5 target distance (world), 0 film
  gate (mm), 1 focal length (mm), 3 zoom, 47 specify FOV, 48 FOV (degrees), 7 specify focus, 6 focus distance, 25 use
  DOF, 41 / 42 horizontal / vertical shift (fraction of the film width), 18 / 40 vertical / horizontal tilt, 4
  distortion, 10 exposure, 32 clip on, 33 / 34 clip near / far (world).
- The FOV 3ds Max and V-Ray render with (`CameraObject::EvalCameraState`, checked against renders): Free / Target:
  the FOV parameter. Physical: specify FOV -> the FOV; else the thin lens focused at d = focus distance (specify
  focus) or target distance, in mm through the system unit: v = 1 / (1/f - 1/d), f_eff = zoom (f + breathing (v -
  f)), FOV = 2 atan(film / (2 f_eff)). VRayPhysicalCamera: specify FOV -> the FOV (no zoom); else the same with
  breathing 1 (v from the focal length and the focus / target distance, times zoom). This changes the rules source
  (`2 atan(film / (2 f zoom))`): V-Ray renders the focused image distance (measured: 39.60 degrees at the default
  200 mm target distance, not 48.46).
- Shift (renders): Physical 20 % moves the image content 0.2 image widths right / up; VRayPhysicalCamera 0.2 the
  same. Blender's shift moves the frame: `shift_x = -h`, `shift_y = -v`, both in image widths (sensor fit
  HORIZONTAL). Tilt corrections are a keystone warp Blender has no equivalent of: an issue.
- Orthographic (render): the view is 2 tdist tan(FOV / 2) wide at any depth; tdist = the free camera's target
  distance, a target camera's distance to its target.
- Cameras look down their local -Z with +Y up, as Blender's: the node transform stays.
- Render settings: the RenderEnvironment object `(0xEE448B23, 0)`, chunk 0x0110 / 0x2000: 0x0190 width (i32),
  0x0200 height (i32), 0x0210 pixel aspect (f32), 0x05F0 present = the render view is locked, its value the 0-based
  viewport index.
- Saved viewports: the `Config` stream, 0x2080 / 0x8200: 0x8210 current layout index; per layout 0x8240 index then
  0x8220: 0x2810 + k viewport k (80 bytes: u32, u32 view type (8 = camera), ..., u32 at byte 76 = the camera
  node's object index), 0x2820 active viewport (i32, -1 when the layout is not current).
- Scene camera: the locked render view, else the active viewport, when it looks through a camera that is built;
  else the first camera in walk order (an issue saying which view it was).

## Mapping

| 3ds Max | Blender camera | Issues |
|---|---|---|
| any | sensor_fit HORIZONTAL, lens = sensor / (2 tan(FOV / 2)) | |
| Free / Target | sensor 36 mm; ORTHO with ortho_scale = 2 tdist tan(FOV / 2) | multi-pass effect |
| Physical | sensor = film width; shift | DOF, tilt, distortion |
| VRayPhysicalCamera | sensor = film gate; shift | DOF, tilt, distortion, exposure |
| clip manually / clip on | clip_start / clip_end in meters | |
| render width, height, pixel aspect | resolution_x / y (100 %), pixel_aspect_x / y | not stored: Blender's kept |
