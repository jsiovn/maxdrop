# Asset table once, scene-level issue labels, unused light helpers (maxdrop-em3.73)

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three small cleanups from the review of maxdrop-0ah.3: one asset-table parse per import, the VRaySky
issue labelled "environment" instead of "object N", and no dead helpers in `convert/lights.py`.

**Architecture:** `ops._import_scene` reads `assets.AssetTable.from_file(cf)` once and hands it to
`convert_scene.describe` and `_material_slots` (both consumers only read it). `desc.issues` indices may now also be
a string: the label of a scene-level issue of its own kind (`convert.scene.ENVIRONMENT = "environment"`);
`convert.report.gather` uses such a label as it is (None stays `"scene"`, an int a node's name). The reason keeps
its `light: ` prefix, as every other reason keeps its category. `lights.describe_light` and `lights.is_vray_light`
are removed.

**Tech Stack:** Python 3.11 (plain unittest), Blender 4.2 / 4.5 / 5.2 headless for the smoke and fixture runs.
