# Shell rim hardened as 3ds Max does Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A converted Shell on an open mesh shades its rim hard against both surfaces, as 3ds Max 2020 does: the
mesh's open (boundary) edges are marked sharp before the Solidify, and what Blender still cannot match (auto smooth
splitting the rim's corners, the override group merging the rim into a surface) is a line in the report
(bead maxdrop-em3.101).

**Architecture:** `convert/scene.py` finds the lowest converted Shell of a node's run (`_rim`): it hardens the rim
when no Mirror is below it and no Smooth-Result smoother (shading SMOOTH) above it. Then the mesh key gains
`("rim", True)` after `("shading", ...)`, on both paths (`_mapped_mesh` direct and through `_extruded`), and
`_mapped_mesh` adds `open_edges()` of the built MeshDescription to `md.sharp_edges` after a SMOOTH smoother below
cleared them, kept sorted and unique. `convert/modifiers.py` carries the Shell's auto smooth, angle and override
in a new defaulted `ModifierDescription.rim` field and no longer names the override issue itself; `scene.py` names
the rim issues once per (Shell, mesh key) and only when the mesh has open edges. `build/modifiers._crease` skips
the mesh's open edges.

**Tech Stack:** Python + numpy (convert/, no bpy), bpy (build/), MAXScript in 3ds Max 2020 for the fixture.

Bead: maxdrop-em3.101

---

## Facts (from the bead, measured in maxdrop-em3.53)

- Open box + Shell 0 / 1: 3ds Max (0, 11, 24), Blender Solidify (0, 3, 16); open edges sharp: (0, 11, 24).
- Plane + Shell, auto smooth on: 3ds Max (0, 6, 12), off (0, 3, 8); Blender with sharp open edges (0, 3, 8).
- Open box, override group 4 of a side, auto smooth off: 3ds Max (0, 9, 22).
- TurboSmooth (Smooth Result) then Shell: 3ds Max (0, 3, 16); Shell then TurboSmooth: (0, 1, 0).
- A Mirror below the Shell is not measured: its weld would turn sharp open edges on the plane into a hard seam.
  No rim there (unchanged behaviour), a debt bead under maxdrop-em3.

## Design decisions

- `rules.ModifierDescription` gets field `rim` (default None; `tests/unit/test_extrude.py` builds it with 8
  arguments): for a Shell `(auto_smooth, angle_degrees, override_group or None)`; override only when its flag is on.
- Auto smooth report: computed, not blanket. At each boundary vertex the two rim faces meet; a rim face of open
  edge a -> b (face winding) has normal (pb - pa) x (na + nb), n the sum of the unit face normals at a vertex (the
  shell's offset direction). A corner whose two rim normals differ by more than the angle is one 3ds Max splits and
  Blender keeps smooth: issue `modifiers: Shell: auto smooth: N corners of the rim sharper than A degrees shade
  smooth (3ds Max splits them)`. The open box (coplanar rim) gets no line; the plane (4 corners of 90) does.
- Override with auto smooth off on a mesh with open edges: `modifiers: Shell: the rim's smoothing group override
  (group G) not converted: the rim stays hard against the surfaces of that group`. Replaces the rules' current
  `smoothing group override not converted` (tests in test_modifier_rules move).
- Named once per (Shell modifier index, mesh key), on the first node of that pair.

## Revisions after implementation

- `RimRule(auto_smooth, angle, override)` is the type of `ModifierDescription.rim`; the override is a group number
  (1 .. 32): probed, group 4 is the open box side of mask 8 and merges (0, 9, 22); groups of no face along the rim
  change nothing.
- Report wording: `modifiers: Shell: auto smooth: N corners of the rim sharper than A degrees shade smooth (3ds Max
  splits the rim there)` and `modifiers: Shell: smoothing group override (group G) not converted: 3ds Max merges
  the rim into the faces along it of that group`. The corner line is computed (`rim_corners`), not named for every
  shelled open mesh as the bead's wording allowed: the open boxes match 3ds Max and get no line. The count is taken
  on the mesh below the modifiers; probed: a plane under 1 to 3 TurboSmooth iterations below its Shell keeps 4 rim
  corners in 3ds Max (6 regions with auto smooth, 3 without).
- Forced companions outside the Files list: `tests/smoke_import.py` (`FIXTURE_ISSUES["stack_shell.max"] = 2`),
  `tests/unit/test_extrude.py` (a Shell above an Extrude: rim key and sharp open edges on the extruded path).
- run.py also gained `PLANE_NORMALS["FixtureShellPlane"]` (a plane's normals point up) and `check_crease_open_edges`
  (`_crease` on a built mesh); `check_converted` expects creases on sharp edges but open ones.
- The oracle of stack_shell was dumped with `dumpFile` in the interactive 3ds Max that saved the fixture; its five
  old entries are unchanged, no other oracle changed.
- Debt: maxdrop-em3.134 (a Shell above a Symmetry keeps the rim smooth: not measured).
- Code review: `rim_corners` measured only the faces at the boundary (`_open_loops`: one int32 and the int64 key
  per loop, as `sharp_edges`): 4M loops 128 MB peak, was 796 MB (`sharp_edges` 208 MB); `check()` between the
  passes of a mesh above `CHECK_EVERY` corners. An animated or unreadable auto smooth, angle or override no longer
  refuses the Shell: the rim lines are left out (an issue). The override line is named whatever the groups of the
  faces along the rim (MeshDescription keeps no groups). A closed mesh under a Shell still gets ("rim", True).
