# Describe-shaped benchmark reference Implementation Plan

> **For agentic workers:** Use subagents when appropriate to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the describe benchmark a reference workload shaped like `convert.scene.mesh_description`, so that its
ratio holds on CI's runners, and set the describe limit from two CI runs of PR #16 (bead maxdrop-em3.83).

**Architecture:** `tests/synthetic_poly.py` gets `describe_reference(values)`: describe's mix of calls (a pass per
face size from `numpy.unique`, rows sorted along axis 1, a stable `lexsort`, `repeat` / `flatnonzero` of the kept
loops, int64 pair keys with a stable `argsort`, the runs of equal keys, `concatenate`, `stack`, a float32 gather)
on the first 3/5 of the loop vertices, plus `numpy_reference`'s streaming work on the first 1/6. Every call
allocates, as describe does. `tests/unit/test_perf.py` and `tests/blender/bench.py` divide describe by it; read and
build keep their references.

**Tech Stack:** Python 3.11 syntax, numpy 1.24.3 to 2.3.4, Blender 4.2 / 4.5 / 5.2.

---

## Model (why these proportions)

The first CI run (bead notes) found describe / `numpy_reference` 3.04-7.91: the old reference (streaming only)
moves with the runner's vector units and numpy 2.x, describe (sorts, allocations) does not. With a reference of
sort share `s` (of describe's own time) and streaming weight `w` (of the old reference's time), the new ratio is
about `1 / (s + w / r_old)`. A limit `L` with `2.2 x max <= L < 3 x min` needs `max / min < 1.36`.

Measured locally (Windows, 1,001,200 faces, Blender 4.2.23's Python 3.11.7 + numpy 1.24.3 and 5.2.0's Python
3.13.13 + numpy 2.3.4):

| sort data | stream data | s | w | ratio |
|---|---|---:|---:|---:|
| 1/2 | 1/2 | 0.34-0.36 | 0.51-0.53 | 2.12-2.20 |
| 3/5 | 1/6 | 0.40-0.44 | 0.15-0.16 | 2.14-2.23 |

The second row predicts 2.12 (r_old 3.04) to 2.27 (r_old 7.91), a spread of 1.07: chosen.
